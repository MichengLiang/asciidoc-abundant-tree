# 025 与段落隔着空行的块标题里的 xref 不进 xrefOccurrences

:发现: 2026-10-30，aat 计划 #12 的 12.2：xref 改由官方转换认定以后，在 26 本书上对照官方的链接数，seekmoon 08 号书有 2 条xref aat 没有收下，都写在与下一段隔着空行的块标题里。
:代码版本: asciidoc-abundant-tree 仓库 ``b9cc8e8``（0.3.0 之前）；0.2.6 同样。
:影响: 这类块标题里的 xref 在图里没有边，按 aat 检查引用的工作区也不检查它们。官方把块标题附到下一段，HTML 里链接照常生成。
:涉及: ``src/metadata-parser.ts:20-38``

## 复现（实测）

.. code-block:: asciidoc

   = T

   == 甲

   .块标题见 xref:甲[]

   段落。

   .紧挨的块标题见 xref:甲[]
   段落二。

Asciidoctor.js 4.1.1 生成两个链接（``#甲``、``#甲``）；aat 只收下第 9 行那一条（紧挨段落的块标题）。

## 原因

规约 09 号书第 8 章把“紧邻”写成元数据附着的前提，aat 照此不把隔着空行的块标题附给下一段，块标题里的文字也就不在任何块的文字区域里，
xref 探测找不到它。官方的 ``Parser.next_block`` 在读块标题以后跳过空行，再把它附给下一个块。

## 方向

元数据怎样附着以官方为准：规约第 8 章的“紧邻”一句按官方的读法改写，扫描器照改。附着规则变了，块的 ``metadataStartLine`` 与标题切片的
起点也会跟着变，修时一起对照。

## 修复要守住的

* 上面两个块标题里的 xref 都进 ``xrefOccurrences``，``officialHref`` 是 ``#甲``。
* 块标题与下一段之间隔着别的块（不只是空行）时，照官方不附。
