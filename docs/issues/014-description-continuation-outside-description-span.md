# 描述折行时，续行不在描述节点的范围里

- 发现：2026-10-22，aat 计划 #8 的 8.9 修描述列表条目的区间时实测。
- 代码版本：asciidoc-abundant-tree 仓库 `40dadad`（0.2.4 之前），0.2.3 同样。
- 影响：描述列表的描述文字折到下一行时，描述节点（`description`）的 `source.span` 只有术语行。续行里的 xref 由描述列表的扫描找到，
  进了 `xrefOccurrences`，RDF 里也有边（按所属 section 判定）；但它不挂在描述节点的 `children` 下，节点树里看不到它属于哪条描述。

## 复现（实测）

```asciidoc
= 文

== 节

正文。

术语:: 解释
续行 xref:x[X]
下一个:: 二
```

第一条的术语与描述的范围都是 `{startLine: 7, endLine: 7}`；`x` 在第 8 行，不在描述节点下。

## 原因

术语与描述在官方 AST 里都是 `list_item`，共用术语行的坐标（`parser.js` 1897-1899 行）。描述的续行与列表条目的续行一样，被官方读成段落
再 `foldFirst` 并进描述的文字（1985-2011 行），并进以后没有自己的坐标。描述列表的投影（`buildDescription`）按描述文本切分范围，只看得到
术语行。

## 方向

描述的范围照列表条目（issue 010）的读法延伸到续行：从术语行起，按官方 text_only 读法与列表里的段落规则（`listItemTextEndLine`）。
术语的范围不变。规约写进 09 号书描述列表的字段章节，并核对标题字段（标题下第一个描述列表）的字段值是否受影响。
