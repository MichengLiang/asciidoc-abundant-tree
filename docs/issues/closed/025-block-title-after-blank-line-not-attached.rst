# 025 与段落隔着空行的块标题里的 xref 不进 xrefOccurrences

:发现: 2026-10-30，aat 计划 #12 的 12.2：xref 改由官方转换认定以后，在 26 本书上对照官方的链接数，seekmoon 08 号书有 2 条xref aat 没有收下，都写在与下一段隔着空行的块标题里。
:代码版本: asciidoc-abundant-tree 仓库 ``b9cc8e8``（0.3.0 之前）；0.2.6 同样。
:影响: 这类块标题里的 xref 在图里没有边，按 aat 检查引用的工作区也不检查它们。官方把块标题附到下一段，HTML 里链接照常生成。
:涉及: ``src/metadata-parser.ts:20-38``

## 复现（实测）

.. code-block:: asciidoc

   = T

   == 甲

   .块标题见 xref:甲[]

   段落。

   .紧挨的块标题见 xref:甲[]
   段落二。

Asciidoctor.js 4.1.1 生成两个链接（``#甲``、``#甲``）；aat 只收下第 9 行那一条（紧挨段落的块标题）。

## 原因

规约 09 号书第 8 章把“紧邻”写成元数据附着的前提，aat 照此不把隔着空行的块标题附给下一段，块标题里的文字也就不在任何块的文字区域里，
xref 探测找不到它。官方的 ``Parser.next_block`` 在读块标题以后跳过空行，再把它附给下一个块。

## 方向

元数据怎样附着以官方为准：规约第 8 章的“紧邻”一句按官方的读法改写，扫描器照改。附着规则变了，块的 ``metadataStartLine`` 与标题切片的
起点也会跟着变，修时一起对照。

## 修复要守住的

* 上面两个块标题里的 xref 都进 ``xrefOccurrences``，``officialHref`` 是 ``#甲``。
* 块标题与下一段之间隔着别的块（不只是空行）时，照官方不附。

## 采纳

:采纳: 2026-10-31，小汤

要做。复测（f72e636，0.5.0）仍复现：隔着空行的块标题里的 xref 没收下，官方生成了两个链接。和 12.2 同一原则：结构由官方认。元数据附着以官方 Parser.next_block 的读法为准（块标题后跳过空行再附给下一块，中间隔着别的块则不附），09 号书第 8 章“紧邻”一句随修复的工作包改写，扫描器照改。记录里提到的 metadataStartLine 与标题切片起点的连带变化，在那一包里对照书架 06–12 号书逐处核对。

## 解决

:提交: 工作包 18.3（git log --grep "Work-Package: 18.3"）

元数据照官方的读法附着（09 号书第 8 章 Metadata Attachment 改写的两段）：collectPrecedingMetadata 从块往回读时越过空行、行注释（`//`）、块注释（`////` 围栏）与属性条目，与 parser.js 的 nextBlock、parseBlockMetadataLines 每读一行元数据就跳过其后空行的读法一致；中间隔着别的块就停。越过空行以后碰到的块标题行要核对：官方读段落时 `.标题` 行不断开段落（readParagraphLines 只在 attribute list、锚点行与分隔符处断开），它可能是上一段的末行，所以只有官方块的标题（getAttributes().title，节的块标题也记在这里）确是这一行时才收下；离块更近处已收下标题时，更远的被覆盖，不再核对。attribute list 与锚点行总会断开段落，不必核对（官方实测：文字/.Foo/[[x]]/空行/段落B，段落B 的 id 是 x、没有标题）。
记录里的例子：两个块标题里的 xref 都进 xrefOccurrences，officialHref 都是 #甲；块标题与段落之间隔着别的块时附给那个块。新增 test/metadata-attachment.test.ts（五种情形：隔空行的块标题、段落末尾的 .Foo、节前隔空行的标题与 [#id]、隔着行注释与块注释、隔着别的块）。
