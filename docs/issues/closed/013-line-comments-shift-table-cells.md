# 表格里有行注释时，单元格与 a| 单元格里的块行号偏小

- 发现：2026-10-22，aat 计划 #8 为 issue 011（段落里的行注释被扫描）核对表格时实测。
- 代码版本：asciidoc-abundant-tree 仓库 `a404488`（0.2.3 之后）。
- 影响：表格里写了行注释，注释之后的普通单元格扫描的是错位的行：注释里的 xref 被当成单元格内容，真正单元格里的 xref 丢失；
  `a|` 单元格里的块坐标偏小。issue 011 修好、扫描跳过注释行以后，偏到注释行上的单元格会整个丢掉。

## 复现（实测）

```asciidoc
= 文

|===
|一
// 注释
|二
// 注释
a|
====
三
====
|===
```

官方给的行号：单元格"一"4、"二"5、`a|` 单元格 6、例子块 7、"三"8；源文是 4、6、8、9、10。

## 原因

官方读表格先 `readLinesUntil({skip_line_comments: true})` 去掉行注释，再交给游标为开始分隔符下一行的新 Reader
（`parser.js` 1266-1276 行），新 Reader 逐行累加，注释行不占编号。与 markdown 引语子块的相对行号（issue 004）同一种情形：
读取器只交出部分源行，编号却逐行累加。

## 方向

照 markdown 引语的换算：表格读出的第 n 行，是从开始分隔符下一行往下、跳过行注释数到的第 n 行源文。

## 解决

2026-10-22，aat 计划 #8 的 8.8（`git log --grep "Work-Package: 8.8"`），随 0.2.4 发布。规约在 09 号书第 7 章新增
「表格里的行注释」。

- 补坐标模块（`src/official-source-location.ts`）把"一个读取器只交出部分源行"抽成共用的编号：从哪一行起、第一条编号是几、
  哪些源行可见。markdown 引语与表格都用它换算读出的块（`relocateReader`），表格同时记下普通单元格的换算（`cellSourceLine`）。
- 读取器嵌套时逐层叠加可见性：markdown 引语里的表格，引语按外层视图跳过一次注释、表格按引语视图再跳过一次（`> // 注释`
  在外层不是注释，在引语里是）；`a|` 单元格里的表格在外层表格的编号上再跳过自己的。嵌套表格的单元格按它自己的编号换算。
- 行注释的判定收成 `isLineComment`（`src/source-lines.ts`）。
- 测试（`test/table-line-comments.test.ts`）：普通单元格与 `a|` 单元格里的块；markdown 引语里的表格（两层注释）；`a|` 单元格里
  嵌套的表格。变异实验：表格不换算、嵌套表格沿用外层编号、嵌套表格不跳自己视图里的注释，都被抓到。
