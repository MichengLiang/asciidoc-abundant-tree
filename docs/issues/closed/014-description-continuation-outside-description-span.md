# 描述折行时，续行不在描述节点的范围里

- 发现：2026-10-22，aat 计划 #8 的 8.9 修描述列表条目的区间时实测。
- 代码版本：asciidoc-abundant-tree 仓库 `40dadad`（0.2.4 之前），0.2.3 同样。
- 影响：描述列表的描述文字折到下一行时，描述节点（`description`）的 `source.span` 只有术语行。续行里的 xref 由描述列表的扫描找到，
  进了 `xrefOccurrences`，RDF 里也有边（按所属 section 判定）；但它不挂在描述节点的 `children` 下，节点树里看不到它属于哪条描述。

## 复现（实测）

```asciidoc
= 文

== 节

正文。

术语:: 解释
续行 xref:x[X]
下一个:: 二
```

第一条的术语与描述的范围都是 `{startLine: 7, endLine: 7}`；`x` 在第 8 行，不在描述节点下。

## 原因

术语与描述在官方 AST 里都是 `list_item`，共用术语行的坐标（`parser.js` 1897-1899 行）。描述的续行与列表条目的续行一样，被官方读成段落
再 `foldFirst` 并进描述的文字（1985-2011 行），并进以后没有自己的坐标。描述列表的投影（`buildDescription`）按描述文本切分范围，只看得到
术语行。

## 方向

描述的范围照列表条目（issue 010）的读法延伸到续行：从术语行起，按官方 text_only 读法与列表里的段落规则（`listItemTextEndLine`）。
术语的范围不变。规约写进 09 号书描述列表的字段章节，并核对标题字段（标题下第一个描述列表）的字段值是否受影响。

## 解决

2026-10-22，aat 计划 #9 的 9.2（`git log --grep "Work-Package: 9.2"`），随 0.2.5 发布。规约在 09 号书第 7 章「描述的文字」
（块锚点 `description-text`，9.1）。

摸底时把官方读描述的代码逐段读过（`parser.js` 1880-2018 行 `parseListItem`、2035-2263 行 `readLinesForListItem`），问题比
上面写的重：

- 描述列表的结束行取后代块的锚点行，最后一条描述只有一行，后面的续行根本不在扫描范围里——续行里的 xref 整个丢了，连
  `xrefOccurrences` 和 RDF 里都没有。写法：最后一条描述折行、续行写在注释行或 `:名: 值` 之后、术语后空一行再写描述、
  缩进续行。
- 术语行带文字时，紧挨的下一块按普通方式读（1994 行），`.标题` 是被并掉的段落的标题、随段落丢弃；aat 整段扫描描述列表，
  只要后面还有一条术语，就把它扫成一条官方不渲染的 xref。
- 术语行没有文字时，官方丢掉术语后的空行（2218 行），坐标却给术语的下一行（1986 行），隔着空行时那是空行：标题字段的值从空行
  起截，是空串。

修法：

- `descriptionText`（`src/official-paragraph.ts`）照官方读法算出描述文字的行、起始列、术语行与段落之间读掉的 metadata 行，以及
  注释行算不算文字（普通方式读的缩进段落不跳过顶格的 `//` 行，1041-1046 行）。紧挨着的那一块是不是段落不移植 `nextBlock`：不是
  段落的块（admonition、两种引语、块宏、分隔线、嵌套列表）留作描述的子块，坐标就在那一行，问官方 AST。
- 区间解析器给描述 `contentSpan`、带列的 `contentSourceSpan` 与 `discardedSpan`；描述列表的结束行算上描述文字的最后一行。
  `SourceInterval.delimited` 改名 `readsLineComments`，表示内容里的注释行是文字（分隔块与上面那种续行）；8.4 留下的"复合块例外"
  是死代码（复合块的替换列表是空的，扫描器从不把它当文字扫），删去。
- 描述列表改为递归：术语与描述各扫自己的文字，读掉的行跳过。投影器的描述 `sourceSpan`、`raw` 跨行；occurrence 是否落在描述里
  按（行，列）比较。
- 术语与描述的分界照官方 `DescriptionListRx`：`用 std::string:: 说明` 的术语是 `用 std::string`，原来按第一个 `::` 切成了 `用 std`。

测试（`test/description-text.test.ts`）：23 种写法拿官方并好的文字（`ListItem#_text`）逐行当裁判；端到端守住找回的 xref、消失的
假 xref、缩进续行里的注释、`std::string`、markdown 引语里的列、标题字段的值。变异实验 9 个都被抓到。

还没修的：描述列表的结束行对其余后代仍只取锚点行，用 `+` 挂上的多行块的尾巴落在 `descriptionList` 的范围外（那些块自己扫描，
xref 不丢），记为 issue 015。
