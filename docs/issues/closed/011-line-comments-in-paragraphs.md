# 段落里的行注释被扫描，产生不存在的 xref

- 发现：2026-10-22，aat 计划 #8 核对列表条目的续行时实测。
- 代码版本：asciidoc-abundant-tree 仓库 `7d93499`（0.2.3）。
- 影响：段落中间以 `//` 开头的注释行里写着 xref 时，它成为一条 occurrence，图里多出一条作者已经注释掉的边。

## 复现（实测）

```asciidoc
= 文

== 节

第一行
// 注释 xref:target[目标]
第二行

[#target]
== 目标
```

`xrefOccurrences` 里有第 6 行的 `target`。Asciidoctor 读段落时跳过这一行，转出的段落里没有这个链接。

## 原因

扫描器逐行扫块的内容区间，不认行注释。只有 `paragraphLine`（`src/source-lines.ts`）在数段落的源行时跳过它们。

## 方向

按 09 号书「Inline 扫描边界」：官方按段落读文字的块（普通段落、隐身段落、列表条目的文字、表格）跳过行注释，扫描同样跳过；
分隔块按分隔符读进的内容不跳过（分隔的 verse 块里的 `//` 行是内容）。

## 解决

2026-10-22，aat 计划 #8 的 8.4（`git log --grep "Work-Package: 8.4"`），随 0.2.4 发布。规约在 09 号书第 7 章「Inline 扫描
边界」行注释一段（8.1）。

- 扫描器跳过行注释，除非块按分隔符读进内容、内容又不是复合的（分隔的 verse）：这种块里的 `//` 行是内容，官方照常替换
  （用 4.1.1 转换实测）。复合块里块与块之间的注释行被当作 metadata 读掉，同样跳过。区间解析器记下块是否按分隔符读
  （`SourceInterval.delimited`）。
- 注释按官方读到的行认：markdown 引语里的 `> // …` 在引语里是注释，按块所在深度的视图判断。普通单元格同样跳过。
- 核对表格时发现单元格行号会被注释行带偏（issue 013），已在 8.8 先修；否则跳过注释行以后，偏到注释行上的单元格会整个丢掉。
- 行注释的判定统一用 `isLineComment`（8.8 引入），`paragraphEndLine`、`listItemTextEndLine` 与引语内容区间都改用它。
- 测试（`test/line-comments.test.ts`）：段落、分隔 verse、markdown 引语、NOTE 段落、列表条目、`[sidebar]` 隐身段落、多行单元格里
  的注释；只有分隔 verse 里的 xref 与条目续行的 xref 留下，注释里的锚点也不进 occurrence。变异实验：段落不跳、分隔块也跳、
  按源行而不按引语视图认注释、单元格不跳，都被抓到。
