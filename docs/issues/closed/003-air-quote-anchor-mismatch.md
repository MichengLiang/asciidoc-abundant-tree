# 空气引号写的引语报 delimiter-not-found

- 发现：2026-10-21，小棉复核 aat 计划 #5 的 5.3 时测出（早于该轮存在）。
- 代码版本：asciidoc-abundant-tree 仓库 `e08953b`（0.2.1 之前）。
- 影响：用空气引号写的引语每处报一条 `source-interval.delimiter-not-found`；坐标仍取自官方，xref 能找到（5.8 之后）。

## 复现（实测）

```asciidoc
= 文

== 节

"引语第一行 xref:a[A]。
第二行。"
-- 某人, 某书

后文。
```

诊断：`source-interval.delimiter-not-found` 在第 5 行；xref `a` 在第 5 行。

## 原因

Asciidoctor.js 4.1.1 把这种段落建成 quote 块（内容模型 simple，`parser.js` 1141-1172 行）：去掉首行开头的 `"`、末行结尾的 `"`，
把 `-- 某人, 某书` 这一行取走作出处。quote 是分隔块的 context，区间解析器在锚点行找不到 `____`，再核对“锚点行是块的第一行源文”
（09 号书「隐身段落」）：官方的第一行少了开头的 `"`，对不上，于是照报。

## 方向

把空气引号认作隐身段落的一种：锚点行以 `"` 开头、块是 quote 时，核对去掉这个 `"` 的文本；块的最后一行还要算上被取走的出处行。
规约写进 09 号书「隐身段落」，官方行号照引。

## 解决

2026-10-22，aat 计划 #7 的 7.2（`git log --grep "Work-Package: 7.2"`），随 0.2.3 发布。照"方向"做，规约在 09 号书
第 7 章另立一节「段落写法的引语」（锚点 `paragraph-quote`），与 004 的 markdown 引语写在一起。

- 区间解析器认出空气引号：锚点行去掉开头的 `"` 后与官方第一行相同。实现时测出方向里漏了一种：内容只有一行时，这一行
  也是被去掉结尾 `"` 的那一行（`parser.js` 1151 行），结尾的 `"` 一并去掉才对得上。
- 范围算上出处行，内容区间不含它；出处行里的 xref 不产生 occurrence，与写在属性列表里的出处相同。
- 新测试：两种空气引号（多行且夹行注释、只有一行）在公开结果上不报诊断、出处行的 xref 不出现；`source-interval-resolver`
  直接断言两者的范围与内容区间。变异实验：不去掉结尾引号、范围不算出处行，都被抓到。
