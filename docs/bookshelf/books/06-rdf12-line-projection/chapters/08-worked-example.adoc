[#worked-example]
== 完整样例

本章使用 `samples/structural-payload.adoc` 展示标题投影图。

=== Source Document

样例中的 `delivery` 和 `capacity` 是标题 address label。`.policy` 和 `.rule` 是标题 role。`.banana` 和 `.pear` 是 payload role，表示作者与下游消费者约定的 schema 或 model label。节点 payload 绑定来自 `for=delivery`。边 payload 绑定来自 xref 的 `payload=rel-delivery` 和 payload block 的手动 ID `rel-delivery`。

[source,asciidoc]
------
= root

一段摘要

[#delivery.policy, status=active, owner=ops]
== 配送策略

配送策略依赖 xref:capacity[运力规则, rel=depends-on, weight=0.8, payload=rel-delivery]。

[.banana, for=delivery]
[source,json]
----
{
  "owner": {
    "team": "ops",
    "fallback": "manual-review"
  },
  "risk": {
    "level": "high",

  }

[source,yaml]
----

[cols="1,1,1,1,1", options="header"]

|`:heading-l5-o0`
|`配送策略`
|`delivery`, `rel-delivery`
|`1`
|line 5 到 line 38

|`:heading-l39-o0`

|`capacity`
|`1`

|`2`

`rel-delivery` 是边 payload block 的本地 target ID。该 ID 按本地非标题 target 规则归属为 `配送策略` 标题节点的 address label。该归属只表示 `rel-delivery` 可以在标题投影图中寻址到 `配送策略` 标题节点，不表示 payload object 成为标题节点。

=== 标题结构

[source,turtle]
----
:heading-l1-o0 aat:containsDirectly :heading-l5-o0 .
:heading-l1-o0 aat:containsDirectly :heading-l39-o0 .
:heading-l39-o0 aat:containsDirectly :heading-l44-o0 .

:heading-l1-o0 aat:documentOrder 1 .
:heading-l5-o0 aat:documentOrder 2 ;
    aat:childOrder 1 .
:heading-l39-o0 aat:documentOrder 3 ;
    aat:childOrder 2 .
:heading-l44-o0 aat:documentOrder 4 ;
    aat:childOrder 1 .
----

`root` 不直接包含 `我是3级标题`。该关系由递归查询推出。同一父标题下的 direct children 通过 `aat:childOrder` 排序；整篇文档的 preorder 通过 `aat:documentOrder` 排序。

=== 节点 Payload

`[.banana, for=delivery]` 表达节点 payload。`.banana` 是 payload role。`for=delivery` 是节点 payload binding marker 和 heading selector。该 payload block 没有手动 ID；节点 payload 不要求手动 ID。

[source,turtle]
----
:heading-l5-o0 aat:payload [
  aat:payloadKind "node" ;
  aat:role "banana" ;
  aat:forSelector "delivery" ;
  aat:format "json" ;
  aat:relativePath "samples/structural-payload.adoc" ;
  aat:startLine 10 ;
  aat:endLine 23 ;
  aat:contentStartLine 13 ;
  aat:contentEndLine 22 ;
  aat:raw """{
  "owner": {
    "team": "ops",
    "fallback": "manual-review"
  },
  "risk": {
    "level": "high",
    "signals": ["weather", "capacity"]
  }
}"""
] .
----

节点 payload 的公共读取路径是 heading 的 `aat:payload`。消费者不需要 payload block ID 来读取该 payload。

=== 本地 Target Address Label 补充样例

本地非标题 target 的 ID 成为所属标题的 address label。以下补充样例中，`capacity-evidence` 是 listing block 的本地 target ID；该 listing 位于 `运力规则` 标题切片内。

[source,asciidoc]
------
[#capacity.rule, status=active]
== 运力规则

运力规则描述系统在不同运力条件下如何判断配送策略是否需要降级。

[#capacity-evidence]
[source,json]
----
{"threshold": 80}
----

[#delivery.policy]
== 配送策略

配送策略读取 xref:capacity-evidence[运力证据, rel=depends-on]。
------

补充样例的投影把 `capacity-evidence` 写为 `运力规则` 标题节点的 address label，并把 xref 关系投影为标题之间的关系边。

[source,turtle]
----
:heading-capacity a aat:Heading ;
  aat:headline "运力规则" ;
  aat:addressLabel "capacity" ;
  aat:addressLabel "capacity-evidence" .

:heading-delivery rel:depends-on :heading-capacity .

:xref-edge-capacity-evidence a aat:XrefEdge ;
  rdf:reifies <<( :heading-delivery rel:depends-on :heading-capacity )>> ;
  aat:sourceHeading :heading-delivery ;
  aat:targetHeading :heading-capacity ;
  aat:targetSelector "capacity-evidence" ;
  aat:displayLabel "运力证据" ;
  aat:officialResolvedId "capacity-evidence" ;
  aat:officialResolvedType "listing" .
----

该投影不创建 listing block 结构节点。消费者通过 `aat:addressLabel "capacity-evidence"` 查到 `运力规则` 标题节点，并读取该标题节点的 `aat:raw` 或标题子树。

=== 验收事实

`samples/structural-payload.adoc` 的投影必须满足：

* 标题节点数量为四个。
* `= root` 创建标题节点。
* `配送策略` 节点有 `aat:addressLabel "delivery"`、`aat:addressLabel "rel-delivery"`、`aat:role "policy"`、`aat:status "active"` 和 `aat:owner "ops"`。
* `运力规则` 节点有 `aat:addressLabel "capacity"`、`aat:role "rule"` 和 `aat:status "active"`。
* `运力规则` 节点自身 raw 不包含 `=== 我是3级标题`。
* `root` 直接包含 `配送策略` 和 `运力规则`。
* `运力规则` 直接包含 `我是3级标题`。
* `配送策略` 和 `运力规则` 在 `root` 的 direct children 中分别拥有 `aat:childOrder 1` 和 `aat:childOrder 2`。
* 四个标题节点的 `aat:documentOrder` 按 `root`、`配送策略`、`运力规则`、`我是3级标题` 连续递增。
* `配送策略` 到 `运力规则` 生成 `rel:depends-on` 边。
* xref `weight=0.8` 投影为边证据上的 `aat:weight "0.8"`。
* xref `payload=rel-delivery` 投影为边证据上的 `aat:payloadSelector "rel-delivery"`。
* `[.banana, for=delivery]` 表达节点 payload。
* 节点 payload 通过 `for=delivery` 绑定为 `配送策略` 的 `aat:payload`。
* 节点 payload 有 `aat:payloadKind "node"`、`aat:role "banana"`、`aat:forSelector "delivery"` 和 `aat:format "json"`。
* 节点 payload 不要求 `aat:payloadId`。
* `[#rel-delivery.pear]` 通过 xref 的 `payload=rel-delivery` 绑定为 `depends-on` 边 payload。
* 边 payload 有 `aat:payloadKind "edge"`、`aat:payloadId "rel-delivery"`、`aat:role "pear"` 和 `aat:format "yaml"`。
* payload format 来自 source block language。
* payload raw 不展开为业务 RDF 图。
* 第 8 行 paragraph 不创建结构节点。
* 第 10 到 23 行节点 payload block 不创建结构节点。
* 第 25 到 37 行边 payload block 不创建结构节点。
* 本地非标题 target ID 作为所属标题的 `aat:addressLabel`，但该 target 不创建 listing、table、block 或 inline anchor 结构节点。
* `role`、`status`、`owner` 和 `weight` 使用直接 `aat:` 谓词，不生成属性资源。
