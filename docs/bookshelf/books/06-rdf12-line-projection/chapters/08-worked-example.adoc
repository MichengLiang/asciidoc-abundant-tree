== 完整样例

本章使用 `samples/structural-payload.adoc` 展示标题投影图。

=== Source Document

样例中的 `.section`、`.payload` 和 `.xref-payload` 是源文档 role token。它们可以投影为 `aat:role` 字段；标题节点身份来自等号标题，节点 payload 绑定来自 `for=delivery-policy`，边 payload 绑定来自 xref 的 `payload=rel-delivery-capacity`。

一段摘要

=== 标题结构

[source,turtle]
----
:heading-l1-o0 aat:containsDirectly :heading-l5-o0 .
:heading-l1-o0 aat:containsDirectly :heading-l41-o0 .
:heading-l41-o0 aat:containsDirectly :heading-l46-o0 .

:heading-l1-o0 aat:documentOrder 1 .
:heading-l5-o0 aat:documentOrder 2 ;
    aat:childOrder 1 .
:heading-l41-o0 aat:documentOrder 3 ;
    aat:childOrder 2 .
:heading-l46-o0 aat:documentOrder 4 ;
    aat:childOrder 1 .
----

`root` 不直接包含 `我是3级标题`。该关系由递归查询推出。同一父标题下的 direct children 通过 `aat:childOrder` 排序；整篇文档的 preorder 通过 `aat:documentOrder` 排序。

=== 本地 Target Address Label 补充样例

本地非标题 target 的 ID 成为所属标题的 address label。以下补充样例中，`capacity-evidence` 是 listing block 的本地 target ID；该 listing 位于 `运力规则` 标题切片内。

[source,asciidoc]
------
[#capacity-rule.section, kind=rule, status=active]
== 运力规则

运力规则描述系统在不同运力条件下如何判断配送策略是否需要降级。

[#capacity-evidence]
[source,json]
----
{"threshold": 80}
----

[#delivery-policy.section, kind=policy]
== 配送策略

配送策略读取 xref:capacity-evidence[运力证据, rel=depends-on]。
------

补充样例的投影把 `capacity-evidence` 写为 `运力规则` 标题节点的 address label，并把 xref 关系投影为标题之间的关系边。

[source,turtle]
----
:heading-capacity a aat:Heading ;
  aat:headline "运力规则" ;
  aat:addressLabel "capacity-rule" ;
  aat:addressLabel "capacity-evidence" .

:heading-delivery rel:depends-on :heading-capacity .

:xref-edge-capacity-evidence a aat:XrefEdge ;
  rdf:reifies <<( :heading-delivery rel:depends-on :heading-capacity )>> ;
  aat:sourceHeading :heading-delivery ;
  aat:targetHeading :heading-capacity ;
  aat:targetSelector "capacity-evidence" ;
  aat:displayLabel "运力证据" ;
  aat:officialResolvedId "capacity-evidence" ;
  aat:officialResolvedType "listing" .
----

该投影不创建 listing block 结构节点。消费者通过 `aat:addressLabel "capacity-evidence"` 查到 `运力规则` 标题节点，并读取该标题节点的 `aat:raw` 或标题子树。

=== 验收事实

`samples/structural-payload.adoc` 的投影必须满足：

* 标题节点数量为四个。
* `= root` 创建标题节点。
* `配送策略` 节点有 `aat:addressLabel "delivery-policy"`、`aat:addressLabel "delivery-policy-payload"`、`aat:addressLabel "rel-delivery-capacity"`、`aat:kind "policy"`、`aat:status "active"` 和 `aat:owner "ops"`。
* `运力规则` 节点自身 raw 不包含 `=== 我是3级标题`。
* `root` 直接包含 `配送策略` 和 `运力规则`。
* `运力规则` 直接包含 `我是3级标题`。
* `配送策略` 和 `运力规则` 在 `root` 的 direct children 中分别拥有 `aat:childOrder 1` 和 `aat:childOrder 2`。
* 四个标题节点的 `aat:documentOrder` 按 `root`、`配送策略`、`运力规则`、`我是3级标题` 连续递增。
* `配送策略` 到 `运力规则` 生成 `rel:depends-on` 边。
* xref `weight=0.8` 投影为边证据上的 `aat:weight "0.8"`。
* xref `payload=rel-delivery-capacity` 投影为边证据上的 `aat:payloadSelector "rel-delivery-capacity"`。
* `delivery-policy-payload` 通过 `for=delivery-policy` 绑定为 `配送策略` 节点 payload。
* `rel-delivery-capacity` 通过 xref 的 `payload=rel-delivery-capacity` 绑定为 `depends-on` 边 payload。
* payload raw 不展开为业务 RDF 图。
* 第 8 行 paragraph 不创建结构节点。
* 第 10 到 23 行 payload listing 不创建结构节点。
* 第 25 到 39 行 xref payload listing 不创建结构节点。
* 本地非标题 target ID 作为所属标题的 `aat:addressLabel`，但该 target 不创建 listing、table、block 或 inline anchor 结构节点。
* `kind`、`status`、`owner` 和 `weight` 使用直接 `aat:` 谓词，不生成属性资源。
