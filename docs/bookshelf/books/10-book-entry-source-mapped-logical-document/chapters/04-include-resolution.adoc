[#include-resolution]
== Include Resolution

Include resolution 读取 source file 中的受支持 include directive，并把目标 source file 的行插入 logical document。

=== 支持表面

本对象支持不带转义前缀的完整行 include directive：整份引入 `include::chapters/01-projection-object.adoc[]`，以及用 `tag`、`tags` 或 `lines` 选取部分行的引入（见 <<selected-include>>）。

Directive 从行首写起，与 Asciidoctor 的 `IncludeDirectiveRx` 相同：行首有空白的 `  include::…[]` 是普通文字，见 <<literal-directive-lines>>。Target path 按包含该 directive 的 source file 所在目录解析。

Escaped include 不执行 resolution。Escaped include 的 source line 以反斜杠开头：`\include::chapters/01-projection-object.adoc[]`。

Escaped include 是普通 source line。它以原文进入 logical document，并保留原始 line origin。

=== 递归 include

Included file 可以继续包含 include directive。Resolution 递归执行，并为插入的每一行记录 origin。只有 AsciiDoc 文件里的 directive 递归展开，见 <<literal-directive-lines>>。

递归 resolution 必须检测循环。循环 include 阻止 logical document 成立，并产生错误诊断。

[#literal-directive-lines]
=== 字面指令行

Asciidoctor 只处理 AsciiDoc 文件里的预处理指令，扩展名为 `adoc`、`asciidoc`、`asc`、`ad` 或 `txt`；入口文件不论扩展名都处理。被引入的其它文件（`.py`、`.md`……）里写着的 `include::` 与条件指令（`ifdef::`、`ifndef::`、`ifeval::`、`endif::`）是这个文件的普通内容：不递归展开，不检查目标是否存在，原样进入 logical document，line origin 登记各自的源行。代码清单引入一份讲解 AsciiDoc 的源文件时，常有这样的行。

AsciiDoc 文件里，行首有空白的指令行同样是普通内容：指令从第 1 列匹配。代码清单里一段 diff 的上下文行（`     include::…#片区[*]`）就是这样，它不展开，也不因属性列表无法映射而让 logical document 不成立。

Logical document 交给 parser 时，parser 会把文本再预处理一遍。官方 Reader 已经消费了全部真正的指令，它输出的行里仍然是指令形状的都是字面内容：上面说的这些行，以及被转义的 include 与条件指令（Reader 去掉了转义的反斜杠）。交给 parser 的文本给这些行加回一个反斜杠，parser 去掉它，得到与官方 Reader 相同的行；不加，parser 会把 include 再展开一次、让条件指令吞掉后面的行。本身以反斜杠开头的字面行无法这样保护，parser 会去掉它的第一个反斜杠。

[#selected-include]
=== 选取引入

Include attrlist 带 `tag`、`tags` 或 `lines` 时，目标文件只有被选中的行进入 logical document。哪些行被选中，以 Asciidoctor 的选取语义为准；line origin 记录每一行在目标文件中的源行号。

Tag 标记行的识别与 Asciidoctor 相同：行中出现 `tag::名称[]` 或 `end::名称[]`，其后是行尾或空白，该行就是标记行，不进入 logical document。注释符号不参与判断：`// tag::x[]`、`# tag::x[]`、`-- tag::x[]` 与 `<!-- tag::x[] -->` 都是标记行。只认 `//` 一种写法会让 Python、SQL 等源文件的选取落空。

实现先自行算出被选中的源行，再与 Asciidoctor 官方 Reader 为这次 include 输出的行逐行对应：官方的这一行属于这次 include 的输出，文本就是这个源行，才登记这个源行号，正文取官方输出的文本。选中的行里有 include directive 时，它照常递归展开，嵌套文件的行登记嵌套文件的坐标。

从某一行起对应不上时（例如选中区域里的条件指令被官方 Reader 吃掉），实现无法知道余下的行各自来自哪里：这次 include 余下的输出登记为 degraded line，source coordinate 保持缺失，并产生一条 `origin-map.selection-mismatch` warning，写明哪一处 include、用的选取写法与缺失坐标的行数。已经对应上的行保留坐标。

官方 Reader 为这次 include 输出的行都在这里消费完。此后的 logical line 继续与官方输出逐行对齐：一处选取对不上，只让这次 include 的一部分坐标缺失，不让后面的标题与引用整体错开。

一次 include 的输出从哪里结束，由官方 Reader 的推入判断：include 每展开一次，Reader 就把当时的状态压进 include stack，这一次推入的行，以及嵌套在它里面更深的推入的行，属于这次 include；紧挨着再引入一次（同一个文件也一样）是另一次推入，就此分界。行号不能用来分界：一次推入的行号从第一条选中的源行起逐行累加，选取有空隙、或选中区域里有被吃掉的条件指令时，就与源行对不上。带 `leveloffset` 的推入，前后各有 Reader 补的两行（`:leveloffset: …` 与空行；空行与 `:leveloffset!:`），按这两行认出，不算选中的源行。

=== Unsupported Attrlist

Include attrlist 若包含本书没有定义的、改变目标文件行集的语义，resolution 不得静默按整文件 include 处理。这些 surface 进入 unsupported include diagnostic。该诊断保护 line origin 的真实性。

=== 路径边界

Resolved include path 必须位于允许边界内。允许边界由 `documentRoot` 或实现定义的 entry root 约束。

越界 include 阻止 logical document 成立。实现不得读取边界外文件后再只发 warning。

=== 与 Asciidoctor 语义的关系

AsciiDoc include 是预处理器行为。未转义完整行 include directive 是构造 logical document 的输入事实。

本对象不实现完整 Asciidoctor preprocessor。它只实现本书定义的 include resolution，选取引入的行集以 Asciidoctor 官方 Reader 的输出为准。其它 AsciiDoc 语义由 parser 在 logical document 上解释。
