[#official-ast-and-source-surface]
== Official AST 与 Source Surface

解析器流水线分离结构权威和源文本证据。Official AST 决定 block identity 和结构关系；source surface 恢复 raw、metadata、span 和 column。

=== Official AST

Asciidoctor official document 提供 section tree、block context、block parent-child relation、refs catalog 和 official xref conversion。

解析器通过 `official-block-walker` 遍历 official block tree。walker 只读取 official block 属性，不扫描源文件。

=== Source Surface

Source surface 是 official block 在源文本中的可恢复表面。它包含 block 起点、metadata、content span、full span、title span 和 diagnostics。

`source-interval-resolver` 以 official block source location 为锚点恢复 source interval。Delimiter 查找只能在 official context 已确认的 block 内局部执行。

[#official-delimiter]
=== 分隔符与它的闭合

锚点行是不是开始分隔符，按 Asciidoctor 自己认分隔符的规则判断（Asciidoctor.js 4.1.1 `Parser.isDelimitedBlock`，`packages/core/src/parser.js` 3056 行；分隔符表 `DELIMITED_BLOCKS`，`constants.js` 269 行）。`--` 只有两个字符。四个字符的分隔符可以用它的最后一个字符加长，`------` 与 `|=====` 都是分隔符；作者加长分隔符，通常是为了在块里写一个用短分隔符的示例。fenced code 是 `+```+`，后面可以跟语言名。

一个分隔符能开出的 context 也按官方的表：分隔符自己的 context，加上它允许伪装成的样式。`....` 带 `[source]` 是 listing，`--` 带 `[quote]` 是 quote，fenced code 是 listing。锚点行是分隔符、并且能开出这个块的 context 时，块到第一行与开始行逐字相同的闭合行为止；fenced code 的闭合行是 `+```+`。

[#cloaked-paragraph]
=== 隐身段落

段落带上 Asciidoctor 的段落样式（`source`、`listing`、`literal`、`pass`、`quote`、`verse`、`example`、`sidebar`、`open`、`abstract`、`partintro` 等，`constants.js` 243 行的 `PARAGRAPH_STYLES`）时，Asciidoctor 用这个段落的行建成该样式的块，不写分隔符（`parser.js` 1007-1012 行，官方把这样的段落记作 cloaked paragraph）。`[source,ts]` 下面直接写一行代码是 listing，`[partintro]` 下面写一段导言是 open 块。

这样的块，锚点行不是分隔符，而是块的第一行源文。区间解析器据此把它读作段落：范围从锚点行起，覆盖官方块的全部源行，不报 `source-interval.delimiter-not-found`。核对第一行时只比可见字符：官方会展开 verbatim 块里的 tab，`indent` 会改行首。锚点行既不是分隔符、也不是块的第一行源文时，坐标与官方块对不上，这条诊断照报：它守着的是坐标漂移，不能因为隐身段落而失去。

段落的最后一行，普通段落与隐身段落一样，从锚点行往下数够官方块的源行数。官方读段落时跳过行注释（`//` 开头、但不是 `///`，`reader.js` 528 行），注释行不在块的源行里，段落却没有断开，所以数的时候同样跳过它们；verbatim 块（listing、literal）不跳。

[#official-paragraph]
=== 官方怎样读段落

有几处范围要知道一个段落读到哪一行为止：markdown 引语的范围、列表条目的续行。它们照 Asciidoctor 读段落的规则算（`parser.js` 3018-3047 行 `readParagraphLines`，`reader.js` 498-531 行 `readLinesUntil`）：从段落的第一行往下读，读到空行、`+` 续接行、块分隔符或块属性行就停，停下的那一行不属于段落；在列表里读时，列表标记行也让段落停下。官方读进的行去掉了行尾空白，只有空白的行就是空行。行注释（`//` 开头、但不是 `///`）被跳过：它不打断段落，也不是读进的行，所以段落的最后一行是最后一条读进的行。

markdown 引语的范围就是官方读进的这个段落，不由它的子块决定。子块可能是列表，列表没有自己的结束线索，只能由它所在的块给出。

[#paragraph-quote]
=== 段落写法的引语

引语除了 `____` 分隔块与 `[quote]` 隐身段落，还有两种直接用段落写出的写法。Asciidoctor 读完段落以后才认出它们是引语（`parser.js` 1102-1172 行）：

* 空气引号：段落第一行以 `"` 开头，倒数第二行以 `"` 结尾，最后一行以 `-- ` 开头。官方去掉第一行开头与倒数第二行结尾的 `"`，取走最后一行作出处，用剩下的行建成内容模型为 simple 的 quote（1141-1172 行）。
* Markdown 引语：段落第一行以 `> ` 开头。官方逐行去掉 `> `，只有 `>` 的行变成空行；最后一行以 `-- ` 开头时取走作出处，再去掉出处之前的空行；剩下的行另建一个 Reader，读成复合的 quote（1102-1140 行）。

两种都不写分隔符。区间解析器认它们的方法与隐身段落相同：锚点行是块的第一行源文，只是核对之前先去掉官方从这一行删掉的引号或前缀。空气引号去掉开头的 `"`；内容只有一行时，这一行也是被去掉结尾 `"` 的那一行，结尾的 `"` 一并去掉。markdown 引语去掉 `> `。范围是官方读进的整个段落（xref:official-paragraph[官方怎样读段落]）：从锚点行起，覆盖内容的行、被取走的出处行，以及 markdown 引语里只有 `>` 的行。内容区间到最后一行内容为止，不含出处行，也不含末尾只有 `>` 的行。出处行里的 xref 不产生 occurrence，与写在属性列表里的出处（`[quote, 某人, 某书]`）相同。

Markdown 引语的子块坐标要换算。官方为去掉前缀的行新建的 Reader 不带游标（`parser.js` 1121 行；Ruby 版 Asciidoctor 2.0.26 同样如此），子块的 source location 没有文件，行号从这个 Reader 的第一行数起。去掉前缀不改变行数，官方读段落时跳过的行注释也不在这些行里，所以第 _n_ 行就是从引语的锚点行往下、跳过行注释数到的第 _n_ 行源文。解析器在给合成的块补坐标的同一处（xref:synthesized-blocks[官方合成的块]）把它们换算成引语所在文件的源行；引语里再嵌套的块一并换算，嵌套的 markdown 引语，它的子块从它自己的锚点行数起。换算之后，引语的子块与正文里的块一样遍历、投影与扫描。

引语里的块，官方读到的是去掉前缀的行：套在几层 markdown 引语里，就去掉几个 `> `。区间解析器对它们的结构判断都按官方读到的行做：锚点行是不是分隔符、闭合行在哪里、第一行源文是否对得上、段落在哪里断开、哪些是块属性行，以及上面说的 markdown 引语本身的认法。所以 `> ====` 是 example 的分隔符，`> ____` 是分隔的 quote，不是又一层 markdown 引语；外层只有 `>` 的行对内层引语是空行，内层的段落在那里结束。span、列号与诊断位置仍取源行。引语里的块属性行记下的是官方读到的那一行。引语里的表格，`a|` 单元格里的块同样换算；普通单元格不是块，没有 source location 可补，它带的行号与表格读自同一个 Reader，按表格的换算取源行。

[#synthesized-blocks]
=== 官方合成的块

Asciidoctor 在两处新建没有 source location 的块，都出现在部（part）的导言里。

* 部下的第一个块既不是 partintro 开放块、也不是不带样式的开放块时（后者会直接被改成 partintro，`parser.js` 557 行），Asciidoctor 新建一个 partintro 开放块，把这个块和它之后、第一个 section 之前的块放进去（`parser.js` 554-565 行、587-596 行）。部下写普通段落、不写 `[partintro]`，就是这种情形。
* `[partintro]` 段落先成为内容为段落文本的 open 块；放进部时，Asciidoctor 把 open 块改成复合块，新建一个段落子块，把文本行交给它（`parser.js` 566-575 行）。这个段落子块没有 source location。

解析器按块是怎样合成的取坐标。合成的容器取第一个有坐标的子块的坐标，范围从第一个子块开始，到下一个兄弟块（部的第一节）之前；它借来的锚点行是子块的，可能是列表项或分隔符，不与容器的第一行源文核对，也不找分隔符。Asciidoctor 给合成的 preamble 补坐标也是取第一个子块的（`parser.js` 632-633 行）。接过父块文本行的段落子块取父块的坐标，范围就是这些文本行，父块的范围到它结束。两者都推不出坐标时，仍报 `source-location.missing`。合成的块不因为没有 source location 而从节点树中消失：它的子块是作者写下的内容。

[#callout-list-location]
=== Callout 列表的坐标

Asciidoctor 建完一个块以后，把读取器上一次 mark 的位置记作块的 source location（`parser.js` 1443 行）。读 callout 列表时，每读一条后续条目都 mark 一次（`parser.js` 1812-1862 行，`parseCalloutList`），所以列表的 source location 落在它的最后一条上，而不是第一条。Ruby 版 Asciidoctor 2.0.26 的 `parse_callout_list` 写法相同。条目自己的 source location 是对的。

解析器在给合成的块补坐标的同一处，让 callout 列表取它第一条的坐标。这样列表的范围从第一条开始，列表前面的块标题与属性行是它的 metadata；遍历、投影与扫描看到的是同一个坐标。

=== 结构权威规则

源码扫描不得创建 official AST 中不存在的 section、listing、table、literal、pass 或 open block。

源码扫描补充 metadata、raw、line span、column span、局部 delimiter confirmation 和 fallback diagnostic。

Fallback 必须锚定 official block。没有 official block 锚点时，解析器不得用全文件正则制造结构。

=== Inline 扫描边界

Inline occurrence scanner 按 official block context 扫描。

Paragraph、带 macros substitutions 的 prose block 和可扫描 table prose 产生 xref 或 anchor occurrence。Listing、literal、pass-through 和 fenced code content 不产生 xref 或 anchor occurrence。

解析器按 official block context 决定扫描、递归还是跳过。Asciidoctor.js 4.1.1 的块 context 以 HTML5 转换器的 `convert_*` 方法为全集（`packages/core/src/converter/html5.js`），归类如下：

[cols="1,3,3"]
|===
|归类 |Context |依据

|扫描
|paragraph、admonition、verse、list_item、dlist、table
|块里是一段做 macros 替换的文字；dlist 扫条目，table 扫单元格。

|递归
|section、preamble、open、example、quote、sidebar、olist、ulist、colist
|块是容器，occurrence 来自子块。写成隐身段落的 example、quote、sidebar、open 例外，见下文。

|跳过
|listing、literal、pass、stem
|内容不做 macros 替换。

|跳过
|thematic_break、page_break、toc、image、audio、video、floating_title
|块没有内容（内容模型为 empty）。

|诊断
|不在上面的 context，例如扩展注册的自定义块
|解析器不知道它的内容怎样替换；块与它的后代都不扫描，报 `official-block-context.unknown`。
|===

跳过只针对块的内容。块标题（`.标题`）与块属性行是块的 metadata，扫描与跳过的块都扫描它们：图片、音频、视频标题里的 xref 照样产生 occurrence。带 ID 的块登记为目标：`[#fig]` 下写 `image::a.png[]`，`xref:fig[]` 解析到这张图；floating_title 的 ID 无论是作者写的还是官方按标题生成的，也一样登记。只有诊断归类的块与它的后代整个跳过。

Occurrence 只来自官方读进块文字的行。官方按段落读文字时跳过行注释（`//` 开头、但不是 `///`，`reader.js` 528 行）：普通段落、隐身段落、列表条目的文字、表格都这样读（`parser.js` 1066、1272、1525 行），这些块里的行注释不产生 occurrence。分隔块按分隔符读进的内容不跳过行注释（`parser.js` 1531 行）：分隔的 verse 块里以 `//` 开头的行是内容，官方照常替换，它的 xref 产生 occurrence。

列表条目（olist、ulist、colist 的 list_item）的文字从标记行起。标记行下面紧挨着的行是续行：官方以只读文字的方式（text_only）读下一个块，读成一个段落，再并进条目的文字（`parser.js` 1985-2011 行，`ListItem#foldFirst`）。读之前先读掉块的 metadata，这时只认锚点行（`[[id]]`）、属性列表行与行注释（`parser.js` 2798-2880 行 `parseBlockMetadataLine`）；`.标题` 这样的行不是 metadata，是条目的文字。读掉的 metadata 随段落并进条目时丢弃。段落在列表里读（xref:official-paragraph[官方怎样读段落]），停在空行、`+` 续接行、块分隔符、块属性行与列表标记行之前（`parser.js` 3029-3036 行），行注释被跳过、不打断段落。紧挨着的不是段落（例如分隔块）时没有续行。续行里的 xref 与标记行上的一样产生 occurrence。用 `+` 挂上的块与嵌套列表是条目的子块，按它们自己的归类扫描。

Section 标题与 floating_title 的标题文字做 macros 替换，标题行里的 xref 与锚点产生 occurrence，与块标题相同。标题文字从 `=` 标记之后算起。Section 标题里的 xref 属于这个 section 自己：投影成 RDF 时，它是从这个标题出发的边。

Open block 是容器。它自身不产生 prose occurrence；occurrence 来自其 paragraph descendants。

Preamble 也是容器：文档标题与第一节之间的块，官方装进一个 preamble 块（book 里，或文档还有别的块时），坐标取它的第一个子块（`parser.js` 632-633 行）。Preamble 的子块与节里的块一样投影与扫描。

写成隐身段落的 example、sidebar、quote 与 open 块（xref:cloaked-paragraph[隐身段落]）不是容器：官方建块时把它们的内容模型从 compound 改成 simple（`parser.js` 1523 行），块里是一段文字，没有段落子块。内容模型为 simple 的这几种块按段落扫描，xref 与 anchor occurrence 来自块自己的文本行。

空气引号同样是内容模型为 simple 的 quote，按段落扫描；markdown 引语是复合的 quote，是容器（xref:paragraph-quote[段落写法的引语]）。

`a|` 单元格的内容是一个内嵌文档。它的 Reader 接着单元格的游标（`table.js` 386、432 行），所以里面的块带着源文件的行号。内嵌文档里的块与正文同规则：同样解析 source interval，按 official block context 决定扫描、递归或跳过。单元格里的 example、sidebar、列表、提示块与正文里的一样产生 occurrence。

=== Section Scope

Section scope 由 official section surfaces 和 source intervals 建立。Table cell、listing、pass-through 或 literal content 中的 section-looking text 不得污染 section tree。

`sectionByLine` 只能来自 official section surfaces。该映射服务 containingSectionId 和下游 source scope 查询。
