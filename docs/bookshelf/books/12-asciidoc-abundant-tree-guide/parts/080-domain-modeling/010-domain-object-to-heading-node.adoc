[#domain-object-to-heading-node]
== 从领域对象到标题节点

领域对象进入书稿时，先判断它是否需要被引用、查询、校验、回源或单独维护。满足这些动作的对象适合作为 heading node。

[source,asciidoc]
----
[.recipe]
== 番茄炒蛋

[.ingredient]
=== 鸡蛋

[.ingredient]
=== 番茄
----

标题节点代表菜谱、食材、规则、运输任务、传感器、图片资产、PDF 证据片段、K8S Service、剧本场景或游戏任务。领域对象的本质复杂度由领域承担；书稿表面降低录入、查询、回源和 agent 协作的偶然复杂度。

对象粒度由消费动作决定。需要独立查询、独立引用、独立校验或独立回源的对象进入标题；只描述某个标题属性的事实进入 field、payload 或正文。

[cols="1,2,2", options="header"]
|===
|领域对象 |标题节点粒度 |下游动作

|菜谱
|菜谱、食材、步骤、分类
|生成组成图、分类图、字段质量报告

|冷链运输
|规则、运输任务、载荷、传感器、处置流程
|查询依赖、监控、触发、边属性和规则约束

|图片资产
|资产组、单张图片、人物、地点、项目
|生成资产索引、重复候选、项目使用报告

|外部文档证据
|claim、chunk、页面区域、段落锚点
|生成 RAG citation index 和原文定位数据

|K8S 配置
|Service、Ingress、Database、ConfigMap
|生成依赖图、blast radius report 和 YAML adapter 输出
|===

这个粒度表不是行业本体；它是建模入口。每个项目仍然用自己的 role、rel、field、payload schema 和 hierarchy policy 固定含义。
