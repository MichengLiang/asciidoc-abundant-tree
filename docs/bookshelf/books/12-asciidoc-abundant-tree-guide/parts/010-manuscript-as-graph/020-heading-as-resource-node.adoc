[#heading-as-resource-node]
== 标题作为资源节点

标题节点由 AsciiDoc 等号标题创建。一个标题节点对应源文档中的一个标题表面，并承担阅读单位、查询单位、回源单位和资源容器。

[source,asciidoc]
----
[#asset-001.photo, status=selected]
== 雨夜街角参考图

location:: 福州
style:: 高对比霓虹

image::assets/rain-street.jpg[]
----

该标题节点代表一张图片资产。图片文件保存在文件系统中；标题节点保存资产名称、字段、嵌入关系和回源位置。

[source,turtle]
----
<urn:aat:doc:...#heading-l1-o0> a aat:Heading ;
  aat:addressLabel "asset-001" ;
  aat:headline "雨夜街角参考图" ;
  aat:role "photo" ;
  aat:status "selected" ;
  aat:location "福州" ;
  aat:style "高对比霓虹" .
----

文件是字节容器；标题节点是书稿中的资源容器。资源文件、外部链接、PDF 页、Kubernetes manifest、剧本场景、业务规则和 RAG chunk 都可以由标题节点命名、描述、连接和回源。资源不必被挤进一个文件边界；资源边界可以由书稿标题声明。

标题节点把异构对象放入同一查询面：

[cols="1,2,2", options="header"]
|===
|资源类型 |标题节点保存的书稿事实 |下游消费动作

|图片资产
|文件路径、版权、地点、视觉模型 payload、项目关系
|生成资产索引、查重复候选、回源补写标签

|PDF 证据段落
|source file、页码、bbox、TextQuoteSelector payload、主张关系
|生成 RAG citation index、打开原文高亮区域

|Kubernetes Service
|端口、依赖、YAML payload、Ingress 关系
|生成配置视图、查询爆炸半径、检查生成物漂移

|叙事场景
|地点、出场角色、解锁任务、分支条件 payload
|生成连续性报告、任务依赖图、分支图
|===

标题节点的粒度由消费动作决定。需要被引用、查询、校验、回源或单独维护的对象适合作为标题节点。只服务段落内部表达的句子留在正文中。这个判断把书稿从线性文本推进到资源图：读者仍然阅读标题和段落；程序沿标题节点、字段、关系和 payload 操作同一份信息。

标题节点也适合 code agent 协作。agent 可以先查询 projection graph，得到目标 heading 的 `relativePath` 和 `headingLine`，再用文本编辑工具修改源书稿。纯文本、图查询、source coordinate 和版本控制形成同一工作环境。
