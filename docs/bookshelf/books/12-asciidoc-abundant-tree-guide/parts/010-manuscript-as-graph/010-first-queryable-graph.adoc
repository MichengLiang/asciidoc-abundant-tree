[#first-queryable-graph]
== 第一张可查询图

一份 AsciiDoc 源文档可以同时成为阅读文本和查询图。作者写标题、字段和交叉引用；投影器输出 RDF 1.2；消费者用 SPARQL 或 TS/JS 查询图，再根据 source coordinate 回到源文件。

[source,asciidoc]
----
= 配送知识库

[#delivery.policy, status=active, owner=ops]
== 配送策略

配送策略依赖 xref:capacity[运力规则, rel=depends-on, weight=0.8]。

[#capacity.rule, status=active]
== 运力规则

priority:: normal
summary::
运力规则描述系统在不同运力条件下如何判断配送策略是否降级。
----

这段源文档创建三类图事实。标题创建 heading node；标题 attrlist 和描述列表创建字段；xref 创建从 `配送策略` 到 `运力规则` 的关系边。源文件仍然是作者编辑对象，projection 是面向查询和消费的图表面。

CLI 输出 Turtle：

[source,bash]
----
asciidoc-abundant-tree source/delivery.adoc --format rdf12 > projection/delivery.ttl
----

Library API 输出同一 projection：

[source,typescript]
----
import { mkdirSync, writeFileSync } from "node:fs";
import { parseAbundantTree, rdf12 } from "asciidoc-abundant-tree";

const document = await parseAbundantTree({ sourcePath: "source/delivery.adoc" });
const projection = rdf12(document, { documentRoot: process.cwd() });

mkdirSync("projection", { recursive: true });
writeFileSync("projection/delivery.ttl", projection.ttl);
writeFileSync("projection/delivery.jsonld", projection.jsonLd);
----

投影图暴露标题节点、字段、关系边和回源坐标：

[source,turtle]
----
@prefix aat: <https://micheng.dev/ns/asciidoc-abundant-tree#> .
@prefix rel: <https://micheng.dev/ns/asciidoc-relation#> .
@prefix field: <https://micheng.dev/ns/asciidoc-field#> .

<urn:aat:doc:...#配送策略> a aat:Heading ;
  aat:addressLabel "delivery" ;
  aat:headline "配送策略" ;
  aat:role "policy" ;
  field:status "active" ;
  field:owner "ops" ;
  rel:depends-on <urn:aat:doc:...#运力规则> ;
  aat:relativePath "source/delivery.adoc" ;
  aat:headingLine 4 .

<urn:aat:doc:...#运力规则> a aat:Heading ;
  aat:addressLabel "capacity" ;
  aat:headline "运力规则" ;
  aat:role "rule" ;
  field:status "active" ;
  field:priority "normal" ;
  field:summary "运力规则描述系统在不同运力条件下如何判断配送策略是否降级。" ;
  aat:relativePath "source/delivery.adoc" ;
  aat:headingLine 9 .
----

`urn:aat:doc:...` 是文档 IRI，`#` 之后是标题节点的名字，也就是引用这一节时写的地址。`delivery` 和 `capacity` 是这两个标题的别名，同样在 heading label space 中。引用写标题原文；消费者从 `aat:name` 读名字，不解析 IRI。

查询 active policy 的依赖：

[source,sparql]
----
PREFIX aat: <https://micheng.dev/ns/asciidoc-abundant-tree#>
PREFIX rel: <https://micheng.dev/ns/asciidoc-relation#>
PREFIX field: <https://micheng.dev/ns/asciidoc-field#>

SELECT ?policyHeadline ?targetHeadline ?path ?line WHERE {
  ?policy aat:addressLabel "delivery" ;
          aat:role "policy" ;
          field:status "active" ;
          aat:headline ?policyHeadline ;
          rel:depends-on ?target ;
          aat:relativePath ?path ;
          aat:headingLine ?line .
  ?target aat:headline ?targetHeadline .
}
----

查询结果同时包含业务事实和编辑坐标：

[source,text]
----
policyHeadline | targetHeadline | path                 | line
配送策略       | 运力规则       | source/delivery.adoc | 4
----

这个闭环是全书的基本形状：源表面写出对象，projection 保存图事实，消费者查询图，报告带着读者或 agent 回到源文件。后续章节扩展这个闭环：字段会进入更丰富的表面，关系会保留边证据，复杂信息会进入 raw value object，多文件书稿会保留 origin source coordinate，领域模型会把结构图解释为业务图。
