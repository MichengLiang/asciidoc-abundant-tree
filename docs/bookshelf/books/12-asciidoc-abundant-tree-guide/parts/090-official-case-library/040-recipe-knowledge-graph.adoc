== Recipe Knowledge Graph

Recipe Knowledge Graph 使用菜谱、食材、步骤和分类说明 role、rel、field 与 hierarchy policy 的组合。低门槛领域让投影图到业务图的转换保持可见。

[horizontal]

projection:: `projection/recipe-knowledge.ttl`、`projection/recipe-knowledge.jsonld`
model:: `model/policy.ts`、`model/business-graph.ts`
reports:: `reports/recipe-graph.json`
views:: `views/classification.mmd`、`views/composition.mmd`、`views/overview.mmd`

=== 源书稿

源书稿把菜谱、食材、步骤和分类都写成 heading node。描述列表保存难度、用量、烹饪时间等字段；xref `rel=is-a` 创建分类关系；标题层级表达组成结构。

[source,asciidoc]
----
[.recipe]
== 番茄炒蛋

difficulty:: easy

番茄炒蛋属于 xref:home-cooking[家常菜, rel=is-a]。

[.ingredient]
=== 鸡蛋

[.ingredient]
=== 番茄
----

=== 建模政策

`policy.ts` 把 child-to-parent 层级解释为 `part-of`。因此 `鸡蛋` 和 `番茄` 作为 ingredient heading，是 `番茄炒蛋` 的组成部分。显式 xref `rel=is-a` 生成分类边，连接菜谱和分类节点。

结构层和业务层在这里分开：`aat:containsDirectly` 是投影事实；`part-of` 是菜谱模型对该事实的解释；`is-a` 来自源书稿里的显式 xref。

=== 输出表面

`business-graph.ts` 读取 heading nodes、description fields、xref edge evidence 和 `aat:containsDirectly`，生成 `recipe-graph.json`。`classification.mmd` 展示分类关系，`composition.mmd` 展示组成关系，`overview.mmd` 把两类关系放在同一图中。

=== 回源意义

业务图中的每个节点都保留 headline、role、fields 和 source line。组合关系来自标题层级；分类关系来自 xref occurrence。报告可以分别指向标题行和 xref 行，使作者知道应该改标题结构、字段还是引用。
