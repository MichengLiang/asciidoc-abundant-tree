[#case-contract]
== 领域闭环契约

书稿源表面、投影图、领域模型、报告和视图放在同一个可运行目录中。领域对象进入标题节点、字段、关系和 payload 后，由 TS/JS 程序消费为查询结果、业务图、适配器输出和回源报告。

=== 目录表面

[source,text]
----
source/      AsciiDoc 或 book-entry 源书稿
projection/  RDF 1.2 Turtle 与 JSON-LD
model/       TS/JS policy、vocabulary、schema、SHACL
reports/     source-aware JSON / Markdown reports
views/       面向消费者动作的视图或 adapter 输出
----

`source/` 是作者编辑对象。`projection/` 是投影器生成的标准图表面。`model/` 保存领域解释政策、schema、查询或 adapter 代码。`reports/` 保存带 source coordinate 的任务结果。`views/` 保存 Mermaid、YAML、CSV、highlight data 或其它消费者表面。

=== 章节表面

每个案例目录固定回答六类对象问题。

[horizontal]
领域对象:: 哪类现实、工程或叙事对象进入书稿资源图。
节点粒度:: 哪些对象成为 heading node，哪些事实成为 field、payload 或正文。
关系政策:: 哪些 xref relation 是显式业务边，标题层级是否生成业务边。
消费程序:: TS/JS 如何读取 projection graph，如何解释 role、rel、field 和 payload。
输出表面:: report、Mermaid、TTL、CSV、YAML 或 adapter data 支持哪个消费者动作。
回源证据:: 输出如何指回源文件、标题行、xref occurrence 或 source value block。

=== 库级检查

库级报告位于 `cases/reports.case-inventory.json`。它记录每个案例的五类目录、projection 文件格式和文件数量。库存量检查命令读取案例目录，验证每个案例包含 `source/`、`projection/`、`model/`、`reports/` 和 `views/`，并检查 projection 目录中存在 Turtle 与 JSON-LD 文件：

[source,bash]
----
pnpm run generate
----

该命令检查目录形状。源表面、建模政策、消费代码、输出视图和回源证据之间的关系由对应章节展开。
