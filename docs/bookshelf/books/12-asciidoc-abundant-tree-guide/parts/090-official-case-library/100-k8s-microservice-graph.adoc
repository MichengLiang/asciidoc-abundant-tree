== K8S Microservice Configuration Graph

K8S Microservice Configuration Graph 面向 Service、Ingress、Database、ConfigMap 和生成 YAML。书稿中的标题节点同时承担配置说明、依赖建模和生成物索引。

[horizontal]
source:: `cases/090-k8s-microservice-graph/source/services.adoc`
projection:: `projection/services.ttl`、`projection/services.jsonld`
model:: `model/k8s-schema.ts`、`model/dependency-report.ts`
reports:: `reports/dependencies.json`、`reports/blast-radius.json`、`reports/drift-check.json`
views:: `views/service-dependencies.mmd`、`views/generated-yaml/`

=== 源书稿

[source,asciidoc]
------
[#svc-orders.service, port=8080]
== orders-service

依赖 xref:db-orders[orders-db, rel=depends-on]，并由 xref:ingress-public[public-ingress, rel=routes-to] 暴露。

[.k8s-manifest, for=svc-orders]
[source,yaml]
----
apiVersion: v1
kind: Service
metadata:
  name: orders-service
----
------

Service 是 heading node。`port` 是短字段。`depends-on` 和 `routes-to` 是显式关系。`k8s-manifest` payload 保存部署工具消费的 YAML 表面。

=== 配置模型

`k8s-schema.ts` 解释 manifest payload。`dependency-report.ts` 查询 `depends-on`、`routes-to` 和配置节点字段，生成 dependencies、blast radius 和 drift check reports。

=== 输出表面

`service-dependencies.mmd` 表达服务、Ingress 和 Database 的依赖关系。`views/generated-yaml/` 保存 adapter 输出的 YAML。`drift-check.json` 比较书稿 payload 与生成物，记录差异对应的 source heading。

=== 回源意义

书稿是可读配置说明，projection graph 是依赖查询面，adapter output 是部署工具消费面。drift check report 把生成物差异带回源 heading，使配置说明、生成物和依赖图保持同一回源链。
