== K8S Microservice Configuration Graph

K8S Microservice Configuration Graph 展示配置、依赖和生成物的一致性管理。领域对象是 Service、Ingress 和 Database。书稿中的标题节点同时承担配置说明、依赖建模和生成物索引。

[horizontal]
source:: `cases/090-k8s-microservice-graph/source/services.adoc`
projection:: `projection/services.ttl`、`projection/services.jsonld`
model:: `model/k8s-schema.ts`、`model/dependency-report.ts`
reports:: `reports/dependencies.json`、`reports/blast-radius.json`、`reports/drift-check.json`
views:: `views/service-dependencies.mmd`、`views/generated-yaml/`

源书稿把 service、database 和 ingress 写成 heading node，并把 Kubernetes YAML 放入 payload：

[source,asciidoc]
------
[#svc-orders.service, port=8080]
== orders-service

依赖 xref:db-orders[orders-db, rel=depends-on]，并由 xref:ingress-public[public-ingress, rel=routes-to] 暴露。

[.k8s-manifest, for=svc-orders]
[source,yaml]
----
apiVersion: v1
kind: Service
metadata:
  name: orders-service
----
------

`k8s-schema.ts` 解释 manifest payload。`dependency-report.ts` 查询 `depends-on`、`routes-to` 和配置节点字段，生成 dependencies、blast radius 和 drift check reports。`views/generated-yaml/` 保存 adapter 输出的 YAML 表面。

这个案例展示配置系统的双向约束：书稿是可读配置说明，projection graph 是依赖查询面，adapter output 是部署工具消费面。drift check report 把生成物差异带回源 heading。
