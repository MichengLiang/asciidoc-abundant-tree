== 构建与投影

构建与投影是两个不同阶段。构建阶段生成聚合 adoc。投影阶段生成 TTL。两个阶段失败时表示不同问题，不能混作一个黑盒动作。

=== 聚合 adoc

聚合 adoc 是 include 展开后的单文件书稿。它保存当前构建视角下的全书线性文本。

书架工作区提供完整构建入口：

[source,bash]
----
cd docs/bookshelf
pnpm build
----

完整构建会生成聚合 adoc、HTML、资源副本和本地资源检查结果。聚合 adoc 输出到：

[source,text]
----
build/adoc/books/<book-id>.adoc
----

聚合 adoc 是投影器输入。它不是原始拆分书稿。作者不应手写修改 `build/adoc/` 下的聚合文件。

=== TTL 投影

TTL 投影由 `asciidoc-abundant-tree` 的 `rdf12` 输出生成。

生成 TTL：

[source,bash]
----
asciidoc-abundant-tree \
  build/adoc/books/<book-id>.adoc \
  --format rdf12 \
  > build/adoc/books/<book-id>.adoc.ttl
----

`--format rdf12` 输出面向 ARQ 查询的 RDF 1.2 Turtle。`.ttl` 是输出文件后缀。调用者不使用 `--format ttl` 或 `--format turtle`。

=== 验证 TTL

TTL 生成后必须验证 Turtle 语法：

[source,bash]
----
riot --validate build/adoc/books/<book-id>.adoc.ttl
----

`riot --validate` 成功表示 Turtle 可解析。它不表示书稿引用全部正确，也不表示查询结果符合作者意图。

=== 生成物纪律

TTL 放在 build 目录下。它属于生成物，可以删除。

源书稿、shared attributes、构建脚本或聚合 adoc 改变后，TTL 必须重新生成。旧 TTL 不能用于当前书稿审计。

作者需要保留 TTL 快照时，应把对应的聚合 adoc 或 source digest 一同纳入判断。只有 TTL 文件本身不足以证明它仍然匹配当前源书稿。

=== 跨项目投影

当投影器位于另一个项目中时，可以从共同工作区根目录运行投影命令：

[source,bash]
----
cd /home/t103o/workbench
asciidoc-abundant-tree \
  projects/ExampleProject/docs/build/adoc/books/example.adoc \
  --format rdf12 \
  > projects/ExampleProject/docs/build/adoc/books/example.adoc.ttl
----

这种运行方式使 source path 保持在当前工作目录之内，也让 TTL 留在被查询项目自己的 build 目录中。
