## 1. 目标定义

标题描述列表元数据挂载机制，是 `asciidoc-abundant-tree` 在 AST 层对 `SectionNode` 的 direct children 起点处第一个连续、扁平 `descriptionList` run 执行的语义提升。该机制把 description list 的 `term` / `description` 映射为标题节点的结构化 metadata fields，使作者使用自然的 description list 写法声明单行或真实多行标题元数据。

该机制只属于项目 AST 后处理层。Asciidoctor 官方 AST 仍把源文本解析为普通 description list。项目公共 AST 保留标题前 metadata surface 与标题下 description list metadata surface 的来源差异。标题前 attrlist 继续存放在 `SectionNode.metadata`。标题下 description list 挂载结果存放在 `SectionNode.descriptionMetadata`。

实现完成后，以下源文档：

```adoc
== 大苹果

类型:: 水果
颜色:: 红色
描述::
这是一个极大且红润的苹果。
它的表面带有清晨的露水。
价格:: 5.99
```

解析得到的 `SectionNode` 持有：

```ts
descriptionMetadata: {
  kind: "headingDescriptionMetadata",
  fields: {
    类型: "水果",
    颜色: "红色",
    描述: "这是一个极大且红润的苹果。\n它的表面带有清晨的露水。",
    价格: "5.99",
  },
  entries: [
    {
      key: "类型",
      value: "水果",
      term: DescriptionTermNode,
      description: DescriptionNode,
    },
  ]
}
```

成功挂载的 description list run 从该 section 的 `children` 中移除。失败挂载的 description list run 原样保留在 `children` 中。

## 3. 语义边界

### 3.1 作用对象

该机制只处理 `SectionNode`。文档 title 不参与。父 section 不读取子 section 的 children。每个 section 独立判断自己的 direct children。

### 3.2 起点规则

执行 agent 实现以下规则：

1. 当 `section.children` 为空时，section 不产生 `descriptionMetadata`。
2. 当 `section.children[0].kind !== "descriptionList"` 时，section 不产生 `descriptionMetadata`。
3. 当 `section.children[0].kind === "descriptionList"` 时，从 index `0` 开始收集连续 `descriptionList` run。
4. run 在遇到第一个非 `descriptionList` child 时结束。
5. run 后方的 description list 不参与该 section 的挂载。

空行不进入 AST children，因此空行不改变起点规则。

### 3.3 扁平规则

候选 run 内任意 descendant 节点的 `kind === "descriptionList"` 时，该 run 失效。失效作用于整个 run。失效时：

1. `section.descriptionMetadata` 不存在。
2. `section.children` 保持原顺序、原节点对象、原结构。
3. RDF direct field projection 不输出该 run 的 fields。

嵌套检查递归进入 `descriptionList.items`、`descriptionListItem.description`、`description.children`、任意节点的 `children`。检查对象是候选 run 的完整节点树。

### 3.4 key/value 规则

成功 run 的每个 `DescriptionListItemNode` 生成一个或多个 entry。

1. key 来自 `DescriptionTermNode.text`。
2. value 来自 `DescriptionNode.text`。
3. `description` 不存在时，value 为 `""`。
4. `description.text` 不存在时，value 为 `""`。
5. 多行 value 保留真实换行字符。
6. 源文本字面 `\n` 保留为两个字面字符，不反解为真实换行。
7. value 不转 number。
8. value 不转 boolean。
9. value 不解析业务单位。
10. 一个 item 中多个 term 共享同一个 value，并生成多个 entry。
11. 重复 key 在 `fields` 中后写覆盖前写。
12. 重复 key 在 `entries` 中完整保序。

### 3.5 source 规则

`HeadingDescriptionMetadataNode.source` 覆盖整个被吸收 run 的源范围。source 由 run 内 descriptionList 的 `source` 合并得到。

合并规则：

1. run 中所有 list 均有 `source.span` 时，`source.span.startLine` 取最小 startLine，`source.span.endLine` 取最大 endLine。
2. run 中所有 list 均有 `source.sourceSpan` 且合并结果位于同一源文件语境时，`source.sourceSpan.start` 取最早位置，`source.sourceSpan.end` 取最晚位置。
3. run 中存在 `source.relativePath` 时，所有非空 `relativePath` 必须相同才写入合并 source；不相同时不写入 `relativePath`。
4. run 中存在 `source.raw` 且各 list 的 source span 连续时，`raw` 使用各 list 的 `source.raw` 按 run 顺序拼接。当前单文件路径中 descriptionList source 未稳定带 raw 时，合并 source 不伪造 raw。
5. source 合并失败不阻止 metadata 挂载；失败时 `source` 字段省略。

该 source 是被吸收 run 的证据，不替代 `term` 和 `description` 引用。entry 必须保留原始 `term` 和 `description` 节点引用。

## 4. 数据模型

执行 agent 修改 `src/model.ts`。

新增类型：

```ts
export type HeadingDescriptionMetadataNode = NodeBase & {
  kind: "headingDescriptionMetadata";
  fields: Record<string, string>;
  entries: HeadingDescriptionMetadataEntry[];
  source?: SourceLayer;
};

export type HeadingDescriptionMetadataEntry = {
  key: string;
  value: string;
  term: DescriptionTermNode;
  description?: DescriptionNode;

```

修改 `SectionNode`：

```ts
descriptionMetadata?: HeadingDescriptionMetadataNode;
```

修改 `AbundantNode` union。`HeadingDescriptionMetadataNode` 进入 union，原因是 serializer、JSON 输出、通用节点工具需要识别其 `kind`。该节点不进入 section 的 `children`。该节点只通过 `section.descriptionMetadata` 到达。

执行 agent 不修改 `MetadataNode.metadataKind`。执行 agent 不新增 `"description"` 或 `"descriptionList"` metadataKind。执行 agent 不把 description metadata 塞入 `SectionNode.metadata`。

## 5. 新增 transform 文件

执行 agent 创建 `src/heading-description-metadata.ts`。

该文件只负责 AST 后处理，不读取文件，不调用 Asciidoctor，不解析源文本，不创建 target，不绑定 xref。

公开函数：

```ts
import type { AbundantDocument } from "./model";

export function attachHeadingDescriptionMetadata(
  document: AbundantDocument,
): AbundantDocument;
```

函数行为：

1. 原地修改并返回传入的 document。
2. 递归处理 `document.children` 中的 section。
3. 每个 section 先处理自身 description list run，再处理剩余 children 中的 child sections。
4. 失败挂载不阻止 child section 递归处理。
5. 成功挂载后，从当前 section 的 `children` 中移除 run，然后递归处理剩余 child sections。

内部函数边界：

```ts
function attachInNodes(nodes: readonly AbundantNode[] | undefined): void;
function attachInSection(section: SectionNode): void;
function leadingDescriptionListRun(children: readonly AbundantNode[]): DescriptionListNode[];
function containsNestedDescriptionList(node: AbundantNode): boolean;
function buildHeadingDescriptionMetadata(run: readonly DescriptionListNode[]): HeadingDescriptionMetadataNode;
function entriesFromRun(run: readonly DescriptionListNode[]): HeadingDescriptionMetadataEntry[];
function mergeRunSource(run: readonly DescriptionListNode[]): SourceLayer | undefined;
```

`containsNestedDescriptionList` 不把候选 run 的根 list 自身视作 nested。它只检查根 list 的 descendants。

实现中使用 `definedObject` 只在已有模式需要省略 undefined 字段时使用。该文件不得引入第三方依赖。

## 8. RDF direct field projection

执行 agent 修改 `src/rdf12-projection/attributes.ts`。

`projectNodeAttributes()` 在 section 分支中投影两类 direct field：

1. 标题前 `metadata` 中 roles 和 attrlist attributes。
2. 标题下 `descriptionMetadata.fields`。

实现结构：

```ts
if (node.kind === "section") {
  projectHeadingMetadataAttributes(graph, nodeIndex, node, node.metadata);
  projectHeadingDescriptionMetadataAttributes(graph, nodeIndex, node);
}
```

`projectHeadingDescriptionMetadataAttributes()` 从 `node.descriptionMetadata?.fields` 读取 entries，使用既有 `addFieldTriple()`。字段 predicate 继续走 `fieldPredicate()`。中文 key 和空格 key 由 `fieldPredicate()` 编码为 `aat:field-${encodeURIComponent(fieldName)}`。测试必须按该编码规则断言。

该 RDF 修改不创建 attribute resource。该 RDF 修改不创建 raw value object。该 RDF 修改不调用 payload projector。该 RDF 修改不把 description metadata entry source 投影为 RDF evidence。

13. 不改动 `samples/关于描述列表/标题描述列表元数据挂载机制需求说明.md`。
14. 不删除未跟踪文件。
15. 不格式化整个仓库。
16. 不执行 git commit。

## 11. 代码质量标准

实现必须满足以下标准：

1. transform 文件的每个函数职责单一。
2. parser 接入点只调用 transform，不内联业务逻辑。
3. nested detection 对 AbundantNode 树递归，逻辑可读。
4. entries 构建只依赖 AST 节点，不依赖源文本。
5. source merge 函数独立存在，不混入 entries 构建。
6. TypeScript 类型不使用 `any`。
7. 测试 helper 不隐藏关键断言。
8. 测试名称直接表达语义规则。
9. 新代码注释只说明 AST surface 边界、source merge 约束、nested 失效理由；不解释显而易见的循环或赋值。
10. 文件内函数顺序保持从 public API 到局部 helper。
11. 失败挂载路径不改变原 children 数组。
12. 成功挂载路径只移除 leading run，不重排 run 后方 children。

## 12. 执行 agent 批次报告格式

执行 agent 完成一个批次后停止，并用以下格式报告：

```text
STATUS: DONE | DONE_WITH_CONCERNS | BLOCKED
BATCH: 批次一 | 批次二 | 批次三 | 批次四

CHANGED FILES:
- path

SEMANTIC SUMMARY:
- one bullet per implemented semantic rule, each bullet names the rule and the file that implements it

VERIFICATION:
- command: pnpm exec vitest run test/heading-description-metadata.test.ts
  result: pass/fail
- command: pnpm exec tsc --noEmit
  result: pass/fail

QUALITY NOTES:
- one bullet per quality decision, each bullet names the affected function or test helper

RISKS:
- none
```

`STATUS: DONE` 表示批次完成定义全部满足。`STATUS: DONE_WITH_CONCERNS` 表示代码和测试完成，但存在需要审核者判断的风险。`STATUS: BLOCKED` 表示执行 agent 无法完成批次，报告必须写出阻塞文件、阻塞原因、已验证事实。

## 13. 主审核者验收规则

主审核者按批次审核。审核顺序固定：

1. 检查 `git diff --stat`。
2. 检查 `git diff`。
3. 检查批次测试命令输出。
4. 检查是否触碰无关文件。
5. 检查禁止实现路径。
6. 检查代码质量标准。
7. 检查用户样例语义。

主审核者通过一个批次后，执行 `git add <paths>` 和 `git commit --only -m "<批次语义标题>" -- <paths>`。提交信息写明语义边界、实现文件、测试证据。主审核者未通过审核时，向同一个执行 agent 发回具体修复清单。执行 agent 修复当前批次，不进入下一批次。

## 14. 最终完成定义

整个功能完成时：

1. `SectionNode.descriptionMetadata` 表达标题下扁平 leading description list run 的 metadata。
2. `SectionNode.metadata` 继续只表达标题前 source metadata surface。
3. 成功挂载移除 children 中的 absorbed run。
4. nested run 失效并保留原 children。
5. 多行 description value 保留真实换行。
6. 字面 `\n` 保留字面字符。
7. 多 term 共享 description 生成多个 entries。
8. 重复 key 的 `fields` 后写覆盖，`entries` 完整保序。
9. JSON 输出包含 `descriptionMetadata`。
10. pretty tree 在 section 中按 `metadata`、`descriptionMetadata`、`children` 顺序输出。
11. RDF heading direct field projection 包含成功挂载的 description metadata fields。
12. RDF nested failure 不输出 description metadata fields。
13. 现有标题前 attrlist metadata 测试通过。
14. 现有 description list parsing 测试通过。
15. `pnpm test` 通过。
16. `pnpm exec tsc --noEmit` 通过。
17. 涉及文件的 `biome check` 通过。
18. git 提交只包含本任务文件。

执行 agent 收到本文档后执行批次一。执行 agent 完成批次一后停止并报告。执行 agent 不执行批次二。执行 agent 不提交 git commit。
