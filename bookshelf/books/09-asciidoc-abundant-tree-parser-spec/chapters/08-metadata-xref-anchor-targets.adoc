== Metadata、Xref、Anchor 与 Target

本章定义 source occurrence 与 target catalog 的关系。解析器保存源文档事实，不决定下游图形状。

=== Metadata Attachment

Metadata surface 附着到紧随其后的 section 或 block。可附着 surface 包括 explicit ID、block title、attribute list 和 block anchor。

附着照官方的读法（`parser.js` 的 `nextBlock` 与 `parseBlockMetadataLines`）：官方每读完一行元数据（attribute list、block anchor、block title，以及夹在其间的行注释、块注释），就跳过其后的空行，再读下一行，直到读出一个块；这些元数据附着给这个块，section 也一样。所以元数据与块之间隔着空行时照样附着；隔着别的块时，元数据附着给那个块，不附给更后面的块。普通文字行本身就是一个块（段落），不是 metadata。

元数据附着决定块的 metadata 起点（`metadataStartLine`）、块标题里的行内文字属于哪个块（其中的 xref 因此有所属的块与标题切片），以及标题切片的起点：标题前隔着空行的 attribute list 同样属于这个标题。

Attribute list 怎样拆，由官方定：哪一段是命名属性、名字是什么、哪一段是位置属性，取官方对源文本里方括号内文字的解析：官方读块属性行时调用 `parseAttributes`（`parser.js` 2839 行），解析器照样调用它，只是不开替换（`sub_input`、`sub_result`），所以拆法与名字照官方，值保留作者写下的样子。不用 `extractAttributesFromText`：它会替换单引号里的值，并另行处理第一个位置属性。只有官方认作命名属性的才是命名属性。`[.dish, 难度=中, 葱、姜=多, a.b=1]` 里，`难度` 是命名属性；`葱、姜=多` 与 `a.b=1` 的名字不合 Asciidoctor 的属性名规则（`[\p{Word}][\p{Word}-]*`），官方把它们读成第 3、4 个位置属性，它们不是命名属性，也就不成为字段（06 号书第 2 章「标题头部属性」）。按逗号自己切开 attrlist 会把它们读成命名属性，引号里的逗号也会被切开。

=== Xref Occurrence

Xref occurrence 是官方认下、并在源文本里找到位置的 xref（xref:Xref 由官方认定[Xref 由官方认定]）。它在源文本中的写法是下面几种：

[source,asciidoc]
----
<<target>>
<<target,label>>
xref:target[label]
xref:target[label,key=value]
----

一个 occurrence 上的事实分属两层：

[cols="1,3"]
|===
|事实 |来自

|`raw`、`syntax`、`sourceSpan`
|源文本：扫描器的候选。

|`target`
|源文本：作者写下的目标原样，如 `{sec}`、`#body-map`。

|`label`、`attributes`
|哪些是命名属性由官方定，值取源文本：对源文本里方括号内的文字调用官方的 `parseAttributes`，不开替换，与块的 attribute list 同一个做法（上一节）。官方转换时用 `extractAttributesFromText` 拆，拆法相同，但它把节点当作 block，单引号里的值经过 replacements（`'a--b'` 变成破折号的实体），不是作者写下的值。`label` 是第一个位置属性。

|`selector`、`document`
|源文本经官方规则得出：在这个位置的属性取值下展开 `target` 的属性引用，再按官方切 `#` 的规则分成文档部分与片段。片段是 `selector`；官方认作别的文档时，文档部分是 `document`。是不是别的文档见下文。

|`asciidoctor` 层的 `href`、`refid`、`path`、`fragment`、`reftext`
|官方 xref 节点。`reftext` 是转换器给出的链接文字。
|===

`selector` 不取官方的 fragment：官方解析成功一个自然引用以后，把 fragment 改写成它找到的 ID（`substitutors.js` 1244 行），`role 的作用域` 成了 `_role_的作用域`，作者写下的文字就丢了；而 label space 按作者写下的标题原文绑定。

是不是别的文档由官方判：路径去掉 `.adoc` 以后等于 `docname`，或登记在 `catalog.includes` 里，就是本文档（`substitutors.js` 1215 行起），官方 xref 节点不带 `path`。带片段的，`refid` 是片段；不带片段的指向这份文档本身，`refid` 为空、href 是 `#`，这时没有 `selector`，也没有 `document`。官方 xref 节点带 `path` 时才是别的文档。

这两样要与官方直接读这个文件时相同，否则同一个引用在 aat 与渲染里读法不同。从文字加载时（single-file 交文字、浏览器入口）补上文件名作 `docname`，官方从文件加载时也是这样设的（`load.js` 104-106 行）。book-entry 的逻辑文档还要带上官方展开 include 时登记的 `catalog.includes`（xref:../10-book-entry-source-mapped-logical-document/book.adoc#Asciidoctor 调用[10 号书：Asciidoctor 调用]）：解析器自己不判断哪个文件属于这本书。

Xref occurrence 不验证外部 target。Interdocument target 保持 raw target 和 official href。

=== Anchor Occurrence

Anchor occurrence 来自 inline 或 block anchor syntax。

[source,asciidoc]
----
[[id]]
[[id,reftext]]
anchor:id[]
----

Anchor occurrence 是官方认下、并在源文本里找到位置的行内锚点，与 xref occurrence 同一个原则、同一个机制：官方转换时，每个行内锚点都交给转换器的 `convert_inline_anchor`（type 为 `ref`），解析器的探测转换器把它们按块、按先后记下，扫描器只给候选与位置，两边对齐。候选照 Asciidoctor 的 inline anchor 正则找：ID 的首字符是字母、`_` 或 `:`，其后是字母、数字、连接标点、`-`、`:` 或 `.`；`[[` 前面紧挨着 `[` 或 `\` 时不是 anchor，`anchor:` 前面紧挨着 `\` 时也不是。

不以官方的 refs 目录（`getRefs()`）为准：它不完整。官方只在读段落时登记行内锚点（`parser.js` 1181 行 `catalogInlineAnchors`），单元格只在文字以 `[[` 开头时登记（`table.js` 528 行）；列表项、描述、单元格、块标题里的锚点都不进目录，转换出的 HTML 里却都有 `<a id>`，链接也到得了。反过来，`+++[[三加号]]+++` 进了目录，转换时却按透传原样输出，HTML 里没有这个锚点。作者写透传，意思就是不要解释这段文字；转换结果与此一致，目录不一致。所以 `+++…+++`、`pass:[]` 里的写法都不是 anchor occurrence。

单独一行的 `\[[id]]` 是块锚点（Metadata Attachment）：它照旧是一个 anchor occurrence，scope 为 block，但它在不在以所附着的官方块的 ID 为准（官方登记的是这个块），不经 `convert_inline_anchor`。

book-entry 下，锚点与 xref 一样先去重、再回源：去重按逻辑文档里的位置做。几个文件在同一行同一列写着同样的锚点时，回源以后行列相同、只是文件不同，在回源之后按行列去重会把它们并成一个；先去重，它们各是一个 occurrence。

参考文献条目是另一种 anchor：`[bibliography]` 样式的无序列表里，列表项文本以 `[[[id]]]` 或 `[[[id,reftext]]]` 开头。它只在这个位置成立；别处的 `[[[id]]]` 按上一条规则不产生 anchor，不会读出以 `[` 开头的 ID。

参考文献条目不经探测，以官方的 refs 目录为准：官方的 `InlineBiblioAnchorRx` 锚定在列表项文字的开头，探测插在前面的标记会让官方认不出它；而官方对这一种的登记是完整的（它只在这个位置成立，读列表项时就登记）。节标题末尾的 `\[[id]]` 也不经探测：官方读标题时用 `InlineSectionAnchorRx` 把它摘下，作为这一节的 ID，所以它与块锚点一样，以官方节的 ID 为准。

[source,asciidoc]
----
[bibliography]
== 参考文献

* [[[parnas1972]]] Parnas, D. L. 1972. On the Criteria To Be Used in Decomposing Systems into Modules.
----

参考文献 anchor 的 syntax 是 `bibliography`，与 inline anchor 一样进入 target catalog，target type 是 `inline-anchor`。

解析器保存 raw anchor、ID、reftext、sourceSpan 和 containingSectionId。

=== Target Catalog

Target catalog 保存当前 source document 内可寻址 target。

Target 来自 section、listing、table、inline anchor 或 block anchor。Target type 是解析器事实，不是下游资源类型。

下游消费者把 target ID 解释为 label、link endpoint、lint 对象或其它投影事实。解析器不决定该投影。

=== Binding Merge

Source layer occurrence 与 official layer binding 必须保持可区分。

Raw xref target 不被 official href 覆盖。Official reftext 不替代 source label。Binding merge 只把两个来源的事实放在同一个 occurrence 上。

Official binding 就是官方在这个位置认下的那个 xref 节点的事实，解析器不为 occurrence 另建 xref 节点去问转换器：另建的节点用的是扫描器给出的目标，官方没有认的文字也会因此得到 href，那是伪造的官方绑定。每个 occurrence 都出自一个官方 xref 节点，所以都带 official href；本文档里找不到的 target 也由转换器给出 `#target`。

`scope` 只记官方事实：官方节点带 `path` 时是 `external`，否则是 `local`。公共模型不下"绑定成功"或"未解析"的结论：引用是否成立，按作者写下的地址在标题投影的 label space 里绑定，结论只由 RDF 投影给出（06 号书第 5 章），规则只在一处。官方按自己的规则解析（无空格的目标当作 ID，同名标题默默取第一个），它的 `resolvedId` 作为官方事实保留，不作为引用是否成立的判断。
