== 标题节点

标题节点由 AsciiDoc 等号标题创建。一个标题节点对应源文档中的一个标题表面。

=== 标题表面

以下表面都创建标题节点：

[source,asciidoc]
----
= root

== 配送策略

=== 我是3级标题
----

一个等号标题、两个等号标题、三个等号标题直到六个等号标题均为标题。投影不因 Asciidoctor 将一个等号标题归入 document title 而取消该标题节点。

=== Headline

`headline` 是作者写下的标题文本：去掉等号标记，展开属性引用，行内标记照原样保留。`` == `book.adoc` 的职责 `` 的 headline 是 `` `book.adoc` 的职责 ``，`== It's A & B -- C` 的 headline 就是 `It's A & B -- C`。

headline 不取 Asciidoctor 转换后的标题：转换替换了引号、符号与行内标记（`It&#8217;s A &amp; B&#8201;&#8212;&#8201;C`），作者按原文写下的引用就对不上它。xref 的 selector 是源文展开属性引用以后的文本（解析器规约第 8 章 Xref Occurrence），headline 与它处在同一个文本层，引用才能按原文绑定。转换后的标题是官方事实，留在官方层。

[source,asciidoc]
----
== 配送策略
----

该标题节点的 `aat:headline` 是 `配送策略`。

=== Level

`aat:headingLevel` 使用解析器恢复出的标题层级坐标。该坐标是 0-based section level 时，源文本中的 `=` 对应 `0`，`==` 对应 `1`，`===` 对应 `2`。

在 `structural-payload.adoc` 中，`== 配送策略` 和 `== 运力规则` 的解析层级是 `1`，`=== 我是3级标题` 的解析层级是 `2`。该数值正确表达标题嵌套层级。

=== 身份

标题节点的 IRI 由投影器生成：`<文档 IRI>#heading-<N>`，`N` 是这个标题的 `aat:documentOrder`，即它在全局 preorder 里的位次（第 4 章「全局顺序」），整份文档内唯一，从 1 起连续。作者写下的字符串，包括 headline、地址路径和 custom ID，都不进入标题节点的 IRI。它们是挂在节点上的标签，见 xref:地址与 Label 空间[地址与 Label 空间]。

RDF 只要求一个资源一个 IRI，并且 IRI 在图里唯一（RDF 1.2 Concepts §1.3）。查询者用标签反查标题节点，不解析 IRI，所以 IRI 不必读得出是哪一节。作者的字符串不能当身份：标题会重名，用它当身份，投影器就得判断哪几个标题算重复、给分不开的编号，这是在替下游解释源文档（第 1 章「标题投影图」）。`aat:documentOrder` 本来就是标题的事实，用它起名不需要任何去冲突的规则；行号在 book-entry 下跨文件相撞，单用行号不能成为身份。

标题节点的 IRI 随编辑变化：前面插入一个标题，后面每个标题的 IRI 都变。它只在一次投影里指称资源。跨投影认同一节，读 `aat:relativePath` 与 `aat:headingLine`，或者用标签查。

文档 IRI 是 `baseIri` 加上源文件相对路径的转写，例如 `urn:aat:doc:books/07-structured-writing-conventions/book.adoc`。相对路径照《名字进入 IRI》转写，另把 `?` 写成 `%3F`：它在 `#` 之前，会被读成查询部分的开头。相对路径是文档在 document root 坐标里的身份，与 `aat:relativePath` 是同一个事实，不是标签。

投影器的其它资源（来源文档、投影、投影活动、源文件、交叉引用边证据、raw value object）也在 `<文档 IRI>#` 下，局部名由投影器按资源类别与位置起：`source`、`projection`、`activity`、`xref-edge-l<行>-c<列>-o<序号>`、`payload-l<行>-o<序号>` 等，各类前缀与 `heading-` 互不相交。标题节点的局部名里没有作者的字符串，所以一节叫《Source》的标题不会与来源资源撞成同一个 IRI。

Turtle 写出时以空前缀 `:` 代表 `<文档 IRI>#`，标题节点写作 `:heading-3`。

示例：

[source,turtle]
----
:heading-2 a aat:Heading ;
  aat:headline "配送策略" ;
  aat:addressLabel "delivery" .
----

`配送策略` 是 headline，`delivery` 是 custom ID，二者都是 `:heading-2` 的标签，都不构成它的身份。

=== 地址与 Label 空间

一节的地址是它的标题原文。标题重名、又要引用其中一个时，用 `::` 往前补直接上级的标题，最长补到从文档标题起的完整路径；custom ID 是这一节的另一个地址，用它也能引用。寻址的范围是整份文档（book-entry 下是整本书），不分文件，没有就近查找，也没有相对寻址。哪种写法算健康的寻址（一处引用只指一节、不写按位置的称呼等），由书的约定规定，在下游检查，投影器不判断。xref 宏写下的目标先由官方判断是不是文档路径，标题原文带 `.` 的会被读成路径；在地址前加 `#` 表明它是本文档里的地址（第 5 章「Target Heading」）。

一个标题的地址都作为标签写在标题节点上，共四个谓词：

`aat:headline`:: 标题原文，即只有一段的地址。
`aat:addressPath`:: 从文档标题到这个标题的各级 headline 依次以 `::` 连接而成的路径，取它的每一个两段以上的后缀，各写一条。家常菜谱里 `== 红烧肉` 下的 `=== 火候` 写 `红烧肉::火候` 与 `家常菜谱::红烧肉::火候` 两条；`火候` 已是 headline，不重复写。
`aat:addressLabel`:: 标题自身的 custom ID，或归属到这个标题的本地非标题 target ID。
`aat:generatedAddressLabel`:: 官方为没有 custom ID 的标题生成的 ID。

这四个谓词的值合起来是标题投影的 label 空间。selector 与标签按整串相等匹配：不拆 `::`，不做规范化，几个谓词之间没有优先级。headline 本身带 `::` 时（`std::vector`），它照样是一个整串；文档里另有 `std` 下的 `vector` 时，`std::vector` 有两个拥有者。selector 绑定标题节点时只查询 label 空间，不查询标题节点 IRI、role、普通字段谓词、xref display label 或 raw 文本。

地址路径要写进图，因为 label 空间要能只靠图读出来。指向别的文档的引用由读得到那份文档的消费者去绑定（第 5 章「Target Heading」），查询者也要按地址反查；他们手里只有图。地址路径也不能只给完整路径、让消费者自己做后缀匹配：`std::vector` 是一个 headline 时，按 `::` 切段的后缀匹配会把它错配给 selector `vector`。按 label 空间绑定的写法是：

[source,sparql]
----
SELECT ?heading WHERE {
  ?heading aat:headline|aat:addressPath|aat:addressLabel|aat:generatedAddressLabel "红烧肉::火候" .
}
----

`aat:addressLabel` 表示标题投影图中可寻址到标题节点的作者声明 label。该 label 来自标题自身手动 ID，或来自归属到该标题切片的本地非标题 target ID。`aat:addressLabel` 不表示该 label 一定写在标题表面。

同一 selector 可以命中多个标题节点。多义命中是源文档事实，投影器必须保留多义结果，不得任意选择一个标题节点作为唯一目标。

=== 本地 Target 的标题归属

AsciiDoc 的本地 target catalog 可以包含 section、listing、table、block、inline anchor 和未知类型 target。标题投影图只把等号标题创建为标题节点；非标题 target 不创建 RDF 结构节点。

本地非标题 target 的 ID 归属为覆盖该 target source span 起始行的最内层标题节点的 `aat:addressLabel`。归属依据是 target 的源位置，不是引用该 target 的 xref 出现位置。source span 缺失的本地非标题 target 不形成 address label。

[source,asciidoc]
------
== 核心引擎设计

[#engine-code]
[source,python]
----
print("warp")
----

== 最终结论

参见 <<engine-code, 代码清单>>。
------

`engine-code` 是 listing block 的本地 target ID。该 ID 在标题投影图中归属为 `核心引擎设计` 标题节点的 address label。

[source,turtle]
----
:heading-1 a aat:Heading ;
  aat:headline "核心引擎设计" ;
  aat:addressLabel "engine-code" .

:heading-2 aat:references :heading-1 .
----

该投影不创建 listing block 结构节点：

[source,turtle]
----
# 不输出：
# :engine-code a aat:ListingBlock .
----

同一 address label 可以归属多个标题节点，这时用它作 selector 的引用绑定到全部这些标题节点（第 5 章「Target Heading」）。同一 address label 在同一标题节点下出现多次时，selector owner 是同一个标题节点，只算一个拥有者。

跨文档 target 不读取外部文件，不归属到当前标题投影图。

=== 标题头部属性

标题头部 attrlist 的 ID、role 和 named attributes 均投影到标题节点。

[source,asciidoc]
----
[#delivery.policy, status=active, owner=ops]
== 配送策略
----

投影为：

[source,turtle]
----
:heading-2 a aat:Heading ;
  aat:headline "配送策略" ;
  aat:addressLabel "delivery" ;
  aat:role "policy" ;
  field:status "active" ;
  field:owner "ops" .
----

named attributes 投影为字段谓词，规则见 xref:Field Predicate[Field Predicate]。字段值作为 literal 保存。投影器不解释 `status` 和 `owner` 的业务语义。标题 role 是源文档表面的作者角色，不参与 selector binding，不决定 heading node 的 RDF type。heading node 的结构身份只来自等号标题。

字段值统一按源文档表面值保存为 string literal。

每个 named attribute 字段另有一个字段证据，写明它写在 attrlist 里、原名与所在的行（第 6 章「字段证据」）。

`#id` 不投影为字段。它投影为 `aat:addressLabel`。点号 role token 不投影为字段谓词。它投影为 `aat:role`。named attribute 才进入 `field:` 下的字段谓词。

位置属性不是 named attribute，不成为字段。`[preface]`、`[appendix]` 里的 `preface`、`appendix` 是第一个位置属性，官方称之为这一节的 style；作者写下的是一个词，没有写下 `style` 这个名字。`field:` 下的字段名是作者写下的名字（字段证据的 `aat:fieldName` 记的就是它），所以 `[preface]` 的标题没有 `field:style`，也没有对应的字段证据。作者写下 `style=炖` 时，`style` 是作者写的名字，照样是字段。

标题 complex property 也使用同一套字段名映射。标题 complex property 的字段名来自 source value block 的 property role，字段值是 raw value object。标题 metadata role 仍只表达标题角色，不表达 complex property 字段名。

=== 标题下描述列表字段

标题下的描述列表也可以承载标题字段。字段较多、字段值较长、需要换行或需要附带代码块时，作者把字段写成标题下的描述列表。

[source,asciidoc]
------
[#close-tab.rule, verdict=adapt]
== 关闭标签

situation:: 关闭当前标签。
evidence:: `editorCommands.ts:835-839`。
+
[source,ts]
----
closeActiveEditor()
----
landing:: core 的 `resources/`。

正文从这里开始。
------

投影为：

[source,turtle]
----
:heading-1 a aat:Heading ;
  aat:headline "关闭标签" ;
  aat:addressLabel "close-tab" ;
  aat:role "rule" ;
  field:verdict "adapt" ;
  field:situation "关闭当前标签。" ;
  field:evidence "`editorCommands.ts:835-839`。\n\n[source,ts]\n----\ncloseActiveEditor()\n----" ;
  field:landing "core 的 `resources/`。" .
----

候选描述列表由标题的直接子块决定。标题的第一个子块是描述列表时，从它开始连续出现的描述列表组成候选串；候选串在第一个不是描述列表的块处结束。标题与描述列表之间的空行不影响判断。第一个子块不是描述列表的标题没有描述列表字段；候选串之后出现的描述列表是正文。

候选串整体成立或整体不成立。以下任一情况使候选串不成立：

* 串中某个描述列表带 ID、块标题、style 或其他块 metadata，例如 `[horizontal]`。带装饰的描述列表是作者排版的正文。
* 串中某个条目的描述里含有嵌套描述列表。嵌套描述列表表达层级结构，压平为字段会丢失这一结构。

不成立的候选串保留为正文，标题不获得其中任何字段。

每个 term 产生一个字段。字段名是 term 的源表面文本。多个 term 共享一个描述时，每个 term 得到同一个字段值。同一字段名在候选串中出现多次时，每次出现各产生一个字段值。

字段值是描述的源文档表面值，取自字段所在源文件的原文，范围从描述在源文件中的起点到该条目的最后一行。条目的最后一行按 AsciiDoc 的列表续接读原文确定：直接文字到空行为止，续接标记挂上的块到它结束为止，空行之后紧跟的列表项或缩进行仍属于条目，细则见解析器规约（09 号书）的 Heading Description Metadata 一节。续接标记 `+` 挂上的段落、listing、表格等块属于字段值。投影器只移除服务于描述列表容器的表面：term、分隔符，以及描述内部把块挂到条目上的外层续接行；外层续接行移除后留下一个空行，块与块之间的分隔因此保留。字段值内部的 AsciiDoc 语法按作者写下的原样保存：行内标记、xref 宏和 include 指令都不被替换或展开。字段值去除行尾空白、公共缩进和首尾空行；源文本中的换行保存为真实换行，源文本中字面的 `\n` 保持为两个字符。

描述列表字段与标题头部 named attributes 使用同一套字段名映射，字段值作为 string literal 保存。投影器不解释字段值的业务语义，也不把字段值中的块解析为结构节点。

同一个名字写在 attrlist 里和写在描述列表里，得到同一条字段三元组；写在哪里由各自的字段证据区分（第 6 章「字段证据」）。

=== 重复 label

重复 headline 合法。重复 address label 按源文档事实保留。按重复 label 查询时，结果可以包含多个标题节点；用它作 selector 时，绑定到全部拥有者。投影器不判断哪几个标题算重复，也不为重复 label 挑出一个目标。
