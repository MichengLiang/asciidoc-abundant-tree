== 地址空间

一节的地址是它的标题原文。xref target selector 和 heading complex property selector 都按地址查询 heading label space。地址模型的规约见 06 号书第 2 章「身份」与「地址与 Label 空间」。

[source,asciidoc]
----
= 指南

[#delivery.policy]
== 配送策略

== 运力规则
----

`配送策略` 的地址是它的 headline `配送策略`，手写 ID `delivery` 是它的另一个地址。`运力规则` 没有手写 ID，projection 为它生成 generated address label。这些地址都是标题节点上的标签；标题节点的 IRI 由投影器按标题在文档里的先后起名，不含作者写的字符串。

[source,turtle]
----
@prefix aat: <https://micheng.dev/ns/asciidoc-abundant-tree#> .
@prefix : <urn:aat:doc:guide.adoc#> .

:heading-2 aat:headline "配送策略" ;
  aat:addressLabel "delivery" ;
  aat:addressPath "指南::配送策略" .

:heading-3 aat:headline "运力规则" ;
  aat:generatedAddressLabel "_运力规则" ;
  aat:addressPath "指南::运力规则" .
----

label space 就是标题节点上四个谓词的值：`aat:headline`、`aat:addressPath`（两段以上的地址路径）、`aat:addressLabel` 和 `aat:generatedAddressLabel`。selector 与标签按整串相等匹配。寻址范围是整份文档，book-entry mode 下是整本书；binding 不按文件或目录就近查找，也没有相对寻址。selector binding 不查询 role、普通字段、raw、display label 或 heading IRI。label space 全部在图上，查询者按地址反查标题，写的是：

[source,sparql]
----
SELECT ?heading WHERE {
  ?heading aat:headline|aat:addressPath|aat:addressLabel|aat:generatedAddressLabel "配送策略" .
}
----

=== 重名与上级标题

按类别组织的书稿里，结构性标题天然重名：每道菜下都有《火候》，每条规则下都有《例外》。重名是源文档事实，只有引用其中一个时才需要消歧。消歧时用 `::` 补上直接上级的标题：

[source,asciidoc]
----
== 红烧肉

=== 火候

== 清蒸鲈鱼

=== 火候

糖色的火候见 xref:红烧肉::火候[红烧肉的火候]。
----

`+xref:火候[]+` 绑定到两节《火候》，边证据上有两条 `aat:targetHeading`，书的检查按约定把它报为一处多指；`+xref:红烧肉::火候[]+` 只绑定到红烧肉下的那一节。补上级标题不是给这一节起第二个名字，只是把同一个地址写全。仍有歧义时继续往前补，最长到从文档标题起的完整路径。链接默认显示目标标题“火候”，读者看不出是哪道菜的，所以这里写上显示文本。

两节《火候》的地址路径都写在图上：一节有 `aat:addressPath "红烧肉::火候"`，另一节有 `aat:addressPath "清蒸鲈鱼::火候"`，两节的 `aat:headline` 都是 `火候`。投影器不判断哪几节算重复，也不给它们另起名字；按 `火候` 反查得到两节，按 `红烧肉::火候` 反查得到一节，由查询者读结果。

custom ID 是同一节的另一个地址。同一父标题下有两个同名小节时，完整路径也分不开它们；这时给要引用的那一节写 `[#id]`，引用写这个 ID。

=== 改名与稳定编号

标题改名，地址随之改变。仍写着旧标题的 xref 在 binding 中成为 unresolved，报告给出源文件与行。作者回到原文判断每一处引用说的是否还是这一节，再改成新标题、改指别的一节或删掉引用。断开的引用是信号：标题改了，旧引用当初指的东西可能已经不是现在这一节。

预先写下的 ID 会让旧引用在改名后照常绑定，这些引用就躲过了检查，ID 里也留着旧的说法。因此，不为可能改名或可能重名的标题预先声明 ID。

需要长期稳定的引用入口时，让稳定的编号成为标题本身，就像 PEP 与 JEP 的编号：

[source,asciidoc]
----
[.requirement, category=performance]
== REQ-2026-0088

系统应在五秒内返回审批记录。
----

`REQ-2026-0088` 是领域内分配的编号，它就是标题，也就是地址。引用直接写这个编号：

[source,asciidoc]
----
测试用例 xref:REQ-2026-0088[rel=verifies]。
----

需求的描述改了，编号不变；编号变了，那就是另一条需求。

作者声明的 ID 由 xref、complex property selector、查询脚本或下游模型消费。没有消费者的手写 ID 只增加维护面。

=== 地址与 HTML

Asciidoctor 自己的 HTML 不按标题原文解析 xref：不含空格的目标被当作 ID，生成 ID 去掉了标点，`::` 也没有对应的锚点。`+xref:名称、角色与关系[]+` 和 `+xref:红烧肉::火候[]+` 在 Asciidoctor 的 HTML 里是断链。引用是否成立以 aat 的 binding 为准；使用方按 binding 结果把 HTML 里的链接接到目标标题上。
